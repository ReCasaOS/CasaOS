## Rulings
- **E1 a live unit always wins over START_FAILED** (#11 #16 #19). When `systemd-run` returns an error the core asks `systemctl show` whether the unit exists (loaded or active): if it does, NO START_FAILED is written (the unit's own UNIT_START will arrive); if systemd does not answer, nothing is written either and the attempt is bounded by the existing StartLost rules; START_FAILED is written only when systemd answered and there is no such unit. In the reducer `open()` depends only on UNIT_END, `Unit.Active` beats START_FAILED, and a UNIT_START after a START_FAILED is accepted and cancels it. The abort/ack/reboot/close paths never act on a run whose unit is active without the typed word.
- **E2 the judge never turns a hole into green** (#8 #9 #10 #12 #17 #40 #41 #59 #39): the judge runs only when systemd answered (NextAction requires `Unit.Answered`; the service also refuses to judge when its own systemctl questions went unanswered); every command of the fact taker has its OWN bounded timeout so one hung command cannot blind the facts taken after it; a context that expired or was cancelled makes the facts `Unknown` for what was not taken and the verdict says so (finding `facts_incomplete`, severity warn, state `succeeded_with_findings`, never plain `succeeded`); a fact known before and impossible to take after is a finding (warn), not silence; for mergerfs the pool's branches and its bind mounts are compared, not only the pool mount point; a default route of type unreachable, blackhole or prohibit is not a default route; containers with a restart policy that are `created` or `restarting` or younger than a few minutes are pending, re-checked for up to 5 minutes (a constant in Timing) before they become `container_not_returned`; the owner can ask for the check again (the existing `resume` action of `succeeded_with_findings` and `failed(verify)` re-runs the judge only, deleting verify.json first); the baseline for comparisons is the snapshot of block 2 (taken at the hop), and what the owner changed in the days between the hop and the restart is reported as `changed_since_snapshot` info, not as an error where the code can tell (otherwise leave it and say so in deviations).
- **E3 an unplaceable log is never idle** (#13 #46): when the log cannot place a run but `Files.PNR` or `Unit.Active` says something is going on, the state is `needs_attention(run_damaged)`, busy; the service sets `Damaged` when the RUN line (run id, kind, plan) disagrees with run.json; the property simulation draws these cases and P4 loses its exemption for idle.
- **E4 the timers always come back** (#5 #14 #24 #28 #32): the unwind restores the timers whenever its own folder says the timers were being stopped, not only when `done-timers` exists: the timers state file is written and fsynced BEFORE the first `systemctl stop` of block 1 and block F, a marker file `timers-stopping` (or equivalent, your choice, named in the contract) is written first, and the unwind restores when either exists; the state file is removed only after the restore succeeded; a STOP, kill or SIGTERM at any line of block 1 or block F leaves the timers running or restores them in the unwind; the manual runbook text for block 1 changes only if it must (the manual golden must stay byte-identical: if the fix needs a manual change, make the change in the auto text only through the existing hook mechanism). Tests: kill after every command line of block 1, of block F inside a refresh unwind, and a STOP inside block 1.
- **E5 a failed restore keeps the evidence and asks for the word** (#6 #33 #49): when the restore script fails the driver does NOT move the backup folder; the state is `needs_attention(unwind_partial)`, busy; leaving it needs the typed word and the status says where the copy of /etc/apt is (the path), plainly; the folder move on `ack` happens only after the restore succeeded; `closeOSUpgradeRun` moves with a copy-then-remove fallback when `os.Rename` fails across file systems and writes ACK only after the move (or states the failure) (#60 #62); a start that fails to write its run folder closes nothing (#63).
- **E6 block F follows the owner's ladder** (#4): `dpkg --configure -a` failing is NOT a stop: print what failed, go on to the simulation of `apt-get -f install` and its guard, then `apt-get -f install`; STOP `dpkg_broken` only if that fails too. The unwind of a refresh runs block F only when its backup folder exists and dpkg is really not quiet after the refresh began to touch dpkg (#34 #47: R0 stopping before the backup must not run F and die).
- **E7 failed(verify) from block 8 is resumable** (#7): `launch` accepts a verify launch from `failed(verify)` and `interrupted` checks; the status offers `resume` only where a launch will be accepted (a test iterates every state x every offered action and asserts the service accepts or refuses coherently with ActionsFor).
- **E8 BOOT_SEEN stops the apt units only while the run still holds the timers** (#18): never after done-after; the stop is guarded by the same condition that block 8 puts them back.
- **E9 abort and close** (#20 #21 #42 #43 #44 #54 #58): abort is not offered or accepted once the refresh upgrade block began (the dpkg block); closing a `needs_attention` run, before or after the point of no return, needs the typed word whenever the sources of Debian 12 may still be in place; the SystemdSilence bound applies to every busy state with no live unit (not while rebooting) giving `needs_attention(systemd_silent)`, and the buttons offered there are only those that can work without systemd (acknowledge with the word); REBOOT_PENDING without `done-prereboot` and VERIFY_DONE without `done-after` are damage, not progress (`RebootBlocked` true; no `succeeded`); a STOP without UNIT_END keeps its class for resumable and State.Class; an unreadable run offers only acknowledge with the word (docs say so); a unit active but hung after the point of no return gets a documented way out (the typed word plus `systemctl stop` is the owner's console action: say it in the status hint, do not invent a button).
- **E10 AppManagement and apps while the machine upgrades** (#1 #2 #3 #22 #23): the busy flag holds in AppManagement every operation that restarts or changes containers on its own: scheduled backups, the automatic git app checks and deployments (periodic check, webhooks, a manual `check now` still reads but a deployment waits), and any automatic image update; user-clicked operations stay available. The catch-up after a hold must not repeat on every following minute tick (save the schedule at the start of the catch-up or serialise it), a backup that started before the flag appeared is detected: the core's start asks AppManagement for its running operations AFTER the flag is written (re-check; refuse with the existing `apps_busy` code if one appeared) and AppManagement reads the flag again right before it marks a backup in progress; the flag is read with Lstat so a dangling symlink is busy in both repositories; one test per held operation and one that uses the production defaults of the seams.
- **E11 locks and handlers** (#57 #66): `osUpgradeMu` is always taken with defer; it is never held across systemctl, systemd-run or any wait (compute outside, re-check under the lock); a test with a panic inside a handler proves the engine is not wedged.
