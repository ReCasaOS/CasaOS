## What this rung is
For the box it runs on, it answers: "if I upgraded now, what exactly would happen?" — WITHOUT changing the machine. It (1) rewrites the box's apt sources to the next release in a temporary tree, (2) lets apt PLAN the upgrade against that tree in a sandbox (real mirror metadata, simulated transaction), (3) parses and judges the plan (what is removed, what is kept back, what protected packages are touched, how much disk and download), (4) gives the plan a `plan_id`, (5) generates, from that plan, the step-by-step runbook for doing the hop by hand (the owner's Debian 11 box will do its first hop with it, with a snapshot). The system is observably the same after as before: nothing under `/etc`, `/var/lib/apt`, `/var/lib/dpkg`, `/var/cache/apt`, `/var/lib/casaos` changes; the only thing written is a private temporary directory that is removed. The button that RUNS the hop is PR 4-5, not here.

SCOPE: Debian 11 -> 12 only (`debian-11-12`; the table of hops that can be planned is ONE Go table, `plan_hops`, with that single row; 12 -> 13 (deb822, `non-free-firmware`, new clues) and Ubuntu are later rungs: every other hop answers `hop_not_planned`). amd64, strict identity from `pkg/ossupport` (reuse the readiness session: a box that is `unsupported`, `latest` or a variant is not planned). ONE-LINE `.list` sources only: a `.sources` (deb822) file anywhere in apt's sources makes the plan refuse with `sources_format` and the file name (the box's own deb822 is a 12 -> 13 matter).

## Architecture (decisions; do not re-open)
- **New pure package `pkg/osplan`** (stdlib only, native tests on Windows): `rewrite.go` (sources), `protected.go` (the guard), `parse.go` (apt output), `plan.go` (assembly, verdict, `plan_id`, estimates, disk), `runbook.go` (text), `seam.go` (the two seams below). **Service glue + routes in the core** (`service/system_os_plan*.go`, `route/v1/system.go`, `route/v1.go`).
- **Runs in the core process as an asynchronous job**, not in a systemd unit: it is read-only, nothing needs to survive a reboot, and a core restart merely loses the plan (the user asks again). One job at a time (a second `POST` while one runs answers the running job's state, 200, `already_running:true`, it does not start another). The plan lives in MEMORY only (no file under `/var/lib/casaos` in this rung), expires 24 h after `made_at`, and a newer plan replaces the older.
- **Two seams, each as small as possible**, so the pure package never touches the machine:
  1. `Files` (read only): `ReadFile`, `ReadDir`, `Lstat`, `FreeBytes`, `Now`: reuse `osreadiness.Probe` itself (the Probe the readiness report already has in `service/system_os_readiness.go`) wherever it fits; do NOT create a second implementation of reading the box.
  2. `Sandbox` (the only thing that writes and runs): `MakeDir() (path string, remove func(), err error)`, `WriteFile(path, content, mode)`, `Run(ctx, argv []string) (Output, error)` where `Output{Text string, ExitCode int, Truncated bool}`. Its production implementation lives in `service/`, and `Run` is guarded by `osplan.AllowedSandboxArgv(argv, sandboxDir)`, a pure function that accepts EXACTLY the argvs this rung runs and refuses everything else (see "What may run"). The fake used by tests records every call; a test asserts that the recorded argvs are all accepted by `AllowedSandboxArgv` and that no fake method writes outside the sandbox dir it handed out.
- **The pure package decides everything that is a rule**; `service/` only wires the seams, the clock, the lock-free job state and the HTTP shape.

## What may run (the allow-list, pinned by a test)

1. `apt-get <SB> update --error-on=any` (timeout 10 min), `apt-get <SB> -s upgrade`, `apt-get <SB> -s dist-upgrade` (2 min each), and `apt-get <SB> -o APT::Get::Trivial-Only=true dist-upgrade` (whenever the transaction has an operation to do, or dpkg has work pending, apt stops at its prompt step with `E: Trivial Only specified but this is not a trivial operation.` before fetching or installing anything; when there is NOTHING to do at all (`0 upgraded, 0 newly installed, 0 to remove`, nothing pending) it ends with status 0, no error and no sizes after a real dist-upgrade of nothing, which changes nothing (real text in `testdata/real/chroot-d11-nothing-size.txt`), and the estimate is then known and ZERO (download 0, extra 0): the verb is pinned by the allow-list, and no other verb may take `Trivial-Only`; exit status 100 is its NORMAL end: apt prints "Need to get ..." and "After this operation ..." and refuses with `E: Trivial Only specified but this is not a trivial operation.`; **a second normal end (review round 2, #5, #11):** when the file system of the sandbox's cache has less room than the download, apt checks it after it printed the two sentences and ends, with status 100 too, with `E: You don't have enough free space in <D>/cache/archives/.` (<D> the sandbox directory: that line, and no other directory's, is read as the end; measured in the Debian 11 chroot with a small tmpfs on the archives, `testdata/real/chroot-d11-12-lowroom-size.txt`), the sizes are above it and are known, and the disk rows and `disk_short` are made from the real room; any other `E:` line, or both ends, is no estimate; nothing is downloaded or installed; the harness-free way to read the sizes, since `-s` prints none; if the real guest says otherwise the plan has `estimates.known=false` and no byte fields, never a guess).
2. `<SB>` = EXACTLY these options, in this order, all paths inside the sandbox dir `D` (no other `-o`, no `-y`, no `-f`, no `install|remove|purge|autoremove|download|source|clean|...` verb): `-o Dir::Etc::sourcelist=D/sources.list -o Dir::Etc::sourceparts=D/parts -o Dir::State::lists=D/lists -o Dir::Cache=D/cache -o Debug::NoLocking=true -o Acquire::Retries=3` (the measured recipe plus the retries of the real hop's apt, which the measurement used too). The environment adds `APT_CONFIG` (next point).

other packages run commands), which would write outside the sandbox. apt reads `Dir::Etc::parts` and `Dir::Etc::main` BEFORE it parses its command line (`pkgInitConfig` runs ahead of the options), so `-o` cannot move them; the file named by the `APT_CONFIG` environment variable is read first and CAN. `D/apt-config` therefore has exactly three statements: `Dir::Etc::parts "D/apt.conf.d";`, `Dir::Etc::main "D/apt.conf";` and `Dir::Log::Planner "";` (apt 2.2.4 and 2.6.1 both write `/var/log/apt/eipp.log.xz`, the log of the last REAL transaction, for every `-s upgrade` and `-s dist-upgrade`, and write nothing when that key is empty: verified in Debian 11 and 12 chroots). apt reads its configuration as a LANGUAGE, not as lines (a comment spliced into a name, `#include`, `#clear`, a brace block, `Dir::Etc::main` or `Dir::Cache::pkgcache` set inside a fragment all got past a filter on the text in real runs), so NOTHING of what the box wrote is copied: from each regular file of `/etc/apt/apt.conf.d/*` (apt's valid names only: letters, digits, `_`, `-` and `:`, since apt 2.2.4 lets a colon in, and a dot only before the extension `conf`, checked against apt itself by `TestRealAptReadsTheFragmentsOfTheNamesWeSay`; a directory in it is passed over without a word, as apt does; at most 200) and from `/etc/apt/apt.conf`, a file is KEPT only if EVERY non-blank line is either a `//` line comment or ONE statement `NAME "VALUE";` (anchored, one per line, no trailing comment) with NAME on the ONE allow-list that the code holds as a single Go table (`sandboxAptSettings`, `pkg/osplan/aptconf.go`; any case, ASCII's; the CI report keeps a python copy of it and the leg a canary fragment for it, so a change is made in the table first): **(the open `Acquire::` prefix of the first version is gone; the list is one Go variable and a test pins it entry by entry)** for the methods `http` and `https` (one binary): `Acquire::<method>::` + `Proxy`, `Timeout`, `Pipeline-Depth`, `Dl-Limit`, `Max-Age`, `No-Cache` or `AllowRedirect`; and, for the three, `Acquire::<method>::Proxy::<host>`, the proxy of one host (the commonest real proxy shape, squid-deb-proxy and apt-cacher: apt 2.2.4 reads it as the proxy of that host only; verified in the Debian 11 chroot; ## The sandbox directory
`/var/tmp/casaos-os-plan.<random>` (`os.MkdirTemp`, mode 0700, root; the name pattern is strict and part of the allow-list). Contents: `sources.list`, `parts/`, `apt.conf.d/`, `apt.conf`, `lists/`, `cache/`. REAL measurement: 214 MiB for the d11 -> 12 plan (lists of the target, with `deb-src`). Floors (decisions, to be re-tared by the CI numbers): refuse with `no_room` (409) unless `FreeBytes("/var/tmp") >= 640 MiB`; the actual size is measured at the end (`du`-like walk in Go, not a command) and reported (`sandbox.bytes`). The directory is removed (`os.RemoveAll` after `Lstat` says it is a directory, not a symlink, and the name matches) on EVERY exit: success, failure, timeout, cancellation, panic (`defer`), and at the core's start the stale ones matching the pattern are removed (only directories, only the strict pattern, older than 10 minutes). A test per exit path.
The measurement's `deb-src` lines are KEPT in the sandbox tree (faithful to what the hop writes; stripping them is a possible later optimisation, not this rung's).

## 1) Rewrite the sources (pure, `rewrite.go`)
Input: the box's `/etc/apt/sources.list` and `/etc/apt/sources.list.d/*` (apt's valid names, `.list` and `.sources`; reuse `osreadiness`'s notion of which files apt reads and its limits: export what you need from `pkg/osreadiness` in ONE small new file rather than duplicating its parsing; the decision "is this repository the distribution's own" has ONE owner, `osreadiness`, which already looks at the address and at the `Origin` of the Release files in apt's lists; the rewriter calls it and REFUSES when it cannot decide). **Fixed after review round 1 (R11, #9, #42, CORE-2):** the exported decider differs from the report's own `markDistro` (which does not change) in what it says when it does not know: an address is the distribution's by its NAME only for Debian's archive hosts (`deb.debian.org`, `cdn-<x>.deb.debian.org`, `security.`, `archive.`, `httpredir.` and `ftp.debian.org`, `ftp[2].<cc>.debian.org`: not `snapshot.`, `people.` or any other host under debian.org, which go by their Release file like any mirror); Docker's host is a third party by its name; a flat repository (a suite that ends in `/`) is not the archive; and an http, https or ftp host whose Release file (InRelease, else Release) apt has not kept, or cannot be read, or an address that no list file name is derived of (`mirror+http`, `mirror://`), is NOT KNOWN (`decided=false`), which `RewriteSources` refuses as `sources_format` with reason `undecided` and the words "run apt-get update first" (it never leaves such a line commented out of the tree). Deviation from the ruling's wording: a flat repository is decided "not the distribution's" (it can never be the archive, and "run apt-get update first" would not help), the ruling counted it among the forms that cannot be derived. Output: `Tree` = the generated files (`sources.list`, `parts/<name>.list`) with their content, and `Findings` = what changed, line by line.
Rules (the measurement's tool is the prior art; port its rules, with these decisions):
- A line is ONE strict form: `deb|deb-src [options] URI SUITE [components...]` (options in `[ ]`, one-line style only) or blank or a comment. Anything else in a file apt reads is `sources_format` (refuse, name file and line number, NEVER guess, never leave a line "as is" that was not understood). A `.sources` file: `sources_format`.
- **Distribution lines**: suite `bullseye` -> `bookworm`, `bullseye-updates` -> `bookworm-updates`, `bullseye-security` -> `bookworm-security`; `bullseye-backports`, `bullseye-backports-sloppy`, `bullseye/updates`-style, `*-proposed-updates` lines are DROPPED (commented `# casaos-dropped: <original>` in the tree; counted `dropped_backports`); `archive.debian.org` -> `deb.debian.org` for the distribution's own address; a suite that is an alias (`stable`, `oldstable`, `testing`...) or already `bookworm`/`trixie` is not a rewrite but a refusal (`sources_alias`/`sources_target`: the readiness report already refuses aliases: the plan refuses too, fail closed, with the line); `non-free-firmware` is appended to the components of a distribution line that has `non-free` and not already `non-free-firmware`.
- **Non-distribution repositories** (Docker's, anyone's): never rewritten. In `sources.list.d/*.list` the whole FILE is PAUSED: it is not in the tree (the real hop will rename it to `<name>.casaos-paused`), listed in `paused[]` with `{file, hosts (scheme+host only, no userinfo/query), docker: bool}`; `docker` = every line of the file is `download.docker.com` (the readiness `dockerHost`). A non-distribution LINE inside `sources.list` itself is commented in the tree (`# casaos-paused: <original>`) and listed `{file:"sources.list", line, hosts}`. A file that mixes distribution and other lines inside `sources.list.d/` is `sources_mixed_file` (refuse: it cannot be paused as a file and rewritten as a file).
- `cdrom:`/`file:` and any URI form the strict parser does not read: `sources_format`/`sources_cdrom` (as the readiness report), never rewritten.
- **Fixed after review round 1 (#40, #41, #44, CORE-2):** a line that the rewrite itself makes longer than 4096 bytes (a component added, the `# casaos-paused: ` or `# casaos-dropped: ` mark) is refused `sources_format` reason `long_line` for that file and line (it was `internal`); `archive.debian.org` is moved to `deb.debian.org` when the address has a port or a user too (kept in the written line); a comment that holds a bidirectional control, a C1 control (U+0080 to U+009F), a format character (Cf: zero width, soft hyphen, the byte order mark) or a line or paragraph separator (U+2028, U+2029) is refused `sources_format` reason `control`.
- The tree is deterministic: files in sorted order, `\n` line ends, a final newline, no timestamps; its SHA-256 (`hash_generated`) and the SHA-256 of the current files (names and bytes, sorted) (`hash_current`) go into the plan. Property tests (random line shapes): the output never contains a `bullseye` suite token on a distribution line, never loses a non-comment line (it is rewritten, dropped, or paused, each counted), is idempotent on its own output refused with `sources_target` (already bookworm), and never emits a line that the strict parser would not accept.
- Real fixtures: the d11 box of the measurement (`d11-12.txt` including `archive.debian.org/debian-security` and the Docker file), a cloud-image style `sources.list` with comments, a file with backports, one with `non-free`, a hostile set (NUL, very long line, CRLF, options with spaces/brackets/quotes, URL with userinfo, `deb [trusted=yes]`: the option is kept verbatim ONLY on distribution lines and `trusted=yes` on a distribution line is `sources_format` refusal).

## 2) Run the plan (service, `service/system_os_plan.go`)
Phases (each is a named phase in the job state and a time in the result): `sources` (read, rewrite, write the sandbox tree and hook-free config) -> `update` -> `upgrade` -> `dist-upgrade` -> `estimate` (Trivial-Only) -> `parse`. A failure of a phase ends the job `failed` with `{code, phase, detail}`; the codes (BINDING, the UI and the CI report use them): `not_root`, `hop_not_planned`, `identity_unsupported` (including `latest`), `busy` (the readiness's `MaintenanceBusy` says something else changes packages; also `apps`: AppManagement unreachable is NOT a reason here, the plan does not need it), `no_room`, `sources_format`, `sources_alias`, `sources_target`, `sources_mixed_file`, `sources_cdrom`, `sandbox_update_failed` (apt's `update` exit != 0 or any `E:`/`W:` line: `detail` has at most 6 sanitised lines, each <= 200 chars of printable ASCII, URLs reduced to scheme+host; `data.kind` in {`no_pubkey`, `not_found`, `network`, `release_change`, `other`} decided from apt's fixed messages: `NO_PUBKEY`, `404`/`Not Found`, `Could not resolve`/`Temporary failure`/`Connection`, `changed its`/`Release file`), `sandbox_solver_failed` (`-s upgrade` or `-s dist-upgrade` exit != 0 or an `E:` line), `plan_unparsed` (the summary line and the sections disagree, a section is missing, an unknown shape: refuse, never partial; **the data of these three failures, `sandbox_update_failed`, `sandbox_solver_failed` and `plan_unparsed`, carry `data.apt_conf_left_out`: the plan's own list of the files of apt's configuration that the sandbox left out, `[{file, reason}]`, the same entries, reasons and order, at most 200, with `data.apt_conf_left_out_truncated: true` when it was cut, and only when at least one file was left out: a proxy in a brace block that was left out is the first thing to look at when the update cannot reach its mirror**), `timeout`, `canceled` (the core shuts down), `internal` (a panic, recovered, detail without stack). `busy` is checked at the start AND again right before the `update`.
No lock of the package updater is taken (the sandbox has `Debug::NoLocking`); the job takes no mutex that `systemPackageUpdater` also takes; a core restart mid-job leaves only a stale sandbox dir, removed at the next start.

## 3) Parse apt's output (pure, `parse.go`) — the formats are REAL (apt 2.2.4 here; keep the parser's tolerance for apt 2.6.1 text)
Fixtures: copy the REAL `sandbox-paused-update.txt`, `-upgrade.txt`, `-dist-upgrade.txt`, `-size.txt` and the `kept` variant of the measured box into `pkg/osplan/testdata/real/` (about 250 KB; keep byte-identical, with their `.rc`). Facts from them: sections are headed by `The following packages will be upgraded:`, `The following NEW packages will be installed:`, `The following packages will be REMOVED:`, `The following packages have been kept back:`, `The following packages were automatically installed and are no longer required:`, followed by indented names (two spaces, wrapped); the summary is `N upgraded, M newly installed, K to remove and L not upgraded.`; `Inst/Conf/Remv` lines are the transaction detail. The plan upgrade (`-s upgrade`) of the measured box was `274 upgraded, 0 newly installed, 0 to remove and 111 not upgraded`; the `dist-upgrade` was `384 upgraded, 75 newly installed, 2 to remove and 0 not upgraded` (removed: `fuse`, `libsemanage1`).
- **The REMOVED section is the authority for removals**, with the summary count as its cross-check (names counted must equal K, else `plan_unparsed`). A `Remv X` line is NOT a removal when a later `Inst X` line names the same package (apt removes and re-unpacks to order a replacement: the measured plan has `Remv cron` then `Inst cron`): a test pins this on the real fixture. `Purg` lines (a package apt would purge) count as removals and are also refused if protected.
- Parse the five sections' name lists; NEW and UPGRADED names also from their `Inst` lines (version from -> to, the repository tag like `Debian:12.15/oldstable`); `Conf` lines are ignored. Summaries must agree with the section name counts, or `plan_unparsed`. The `E:` line anywhere => `sandbox_solver_failed`. A section that appears twice, a name that is not `^[a-z0-9][a-z0-9+.:~-]*$` (arch suffix `:amd64` allowed), more than 20000 names, or a line > 4096 bytes => `plan_unparsed`.
- `Need to get ...`/`After this operation ...`: parse apt's fixed English forms (`Need to get X of archives.`, `Need to get X/Y of archives.`; `After this operation, X of additional disk space will be used.`, `After this operation, X disk space will be freed.`, with `kB`/`MB`/`GB`, thousands separators `,`, and apt's rounding): produce `download_bytes` (the Y of `X/Y`, i.e. what must be fetched when none is cached... DECISION: use the FULL archive size Y, the safe one), `extra_bytes` (negative when freed). Any other shape => `estimates.known=false`.
- **Fixed after review round 1 (R12, #8, #33, #34, #36, #66, CORE-2); real texts of apt 2.2.4 in `testdata/real/chroot-d11-*`.** (1) apt's warning `WARNING: The following essential packages will be removed.` + `This should NOT be done unless you know exactly what you are doing!` + indented names (each alone or `name (due to other)`, wrapped between names, a `(due to ...)` may be cut over two lines) is parsed: its names must all be in REMOVED (`essential_not_removed` otherwise), the plan marks them `essential`, and `removal_essential` blocks. ## 5) Routes (core), JWT group, in the style of `/sys/docker/update`
- `POST /v1/sys/os/upgrade/plan` (with `headerTokenOnly`, as the docker update POST): starts the job (202 `{state:"running", phase:"sources", started_at}`) or answers the running one (200, `already_running:true`); an immediate refusal is 409 with `data.error_code` from the codes above (`not_root`, `hop_not_planned`, `identity_unsupported`, `busy`, `no_room`).
- `GET /v1/sys/os/upgrade/plan`: `{plannable: bool, reason?: code (hop_not_planned | identity_unsupported | not_root), unknown?: true, state: idle|running|done|failed, phase, started_at, finished_at, expires_at, expired?: true, error?:{code,phase,detail,data}, sandbox_left_behind?: string, plan?: Plan-without-tree}`, and the answer to the POST that found a job running has `already_running: true` too. `unknown: true` (and no `reason`) says that the question "can a plan be made for this box" could not be answered (a command of the identity checks failed or took too long): a glitch is not a box that cannot be planned, and the page asks again. `sandbox_left_behind` is the FULL PATH of the sandbox directory that a job that is over could not remove, like `/var/tmp/casaos-os-plan.481516` (and nothing of what was in it; the next start of the core removes it once it is ten minutes old). **Cost (corrected: the first text said "no apt, in milliseconds", and the identity gates were added):** it runs no apt and takes no lock of the package updater; while a job runs it only reads the state; otherwise it asks who the box is (the identity gates of the readiness report: `dpkg --print-architecture` and the like), bounded to 30 s and shared by a singleflight among the requests that come together, so that a page that asks again and again does not make the box run them again and again; an expired plan is `idle` with `expired:true`.
- `GET /v1/sys/os/upgrade/runbook`: 409 `no_plan` when there is no valid plan (idle, failed, expired, or `verdict:"blocked"`: a blocked plan has no runbook, the problems say why); 200 `{plan_id, hop, text, blocks:[{id, title, reboot:bool, point_of_no_return:bool}]}`.
- A swagger comment for each as the neighbours have; handler tests with a fake service (envelope, codes, 409 shapes, method not allowed); `route/v1.go` wiring test if the neighbours have one.
