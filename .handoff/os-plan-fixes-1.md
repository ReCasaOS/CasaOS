## Rulings (decisions of the controller; do not re-open)
- **R1 rename**: the plan JSON field `apt_hooks_left_out` becomes `apt_conf_left_out` everywhere (core JSON and Go, UI, CI report and harness, spec). Each entry: `{file, reason}` with `reason` in {`not_simple`, `has_directive`, `not_allowed_setting`, `too_large`, `not_regular`, `proxy_auto_detect`}.
- **R2 default-deny sandbox apt config** (findings #16, #17, #59, #18 core side): apt reads its configuration as a LANGUAGE (comment splicing `Post-In/**/voke`, `#include`, `#clear`, `Dir::Etc::main` set inside a fragment, `Dir::Cache::pkgcache` set in a fragment all got past the text filter in the reviewers' real runs). So the text filter (`Invoke|dpkg|Pre-Install`) is REPLACED by a grammar: from each real `/etc/apt/apt.conf.d/*` fragment and from `/etc/apt/apt.conf`, a file is kept ONLY if EVERY non-blank line is either a `//` line comment or a single statement that matches, anchored, `NAME "VALUE";` with NAME = `Acquire::` followed by `[A-Za-z0-9-]+(::[A-Za-z0-9-]+)*` (but not a name ending in `Proxy-Auto-Detect` or `ProxyAutoDetect`, which runs a script: reason `proxy_auto_detect`) or exactly `APT::Install-Recommends` or `APT::Install-Suggests`, and VALUE = `[^"\\]*` printable ASCII without quotes or backslashes (<= 512 chars). Kept files are RE-EMITTED canonically (one `NAME "VALUE";` per line, comments dropped), never copied byte for byte. Anything else (a `#` directive, `/* */`, a brace block `Acquire { ... };`, any other setting, a binary or too large file, a symlink or non-regular file) leaves the WHOLE file out and names it with its reason in `apt_conf_left_out`. Plans on boxes with a brace-style proxy therefore fail with `sandbox_update_failed` kind `network` and the left-out list says why: accepted. `D/apt-config` becomes exactly three statements: `Dir::Etc::parts "D/apt.conf.d";`, `Dir::Etc::main "D/apt.conf";`, `Dir::Log::Planner "";` (verify in the chroot that the last one stops `/var/log/apt/eipp.log.xz` from being written by `-s upgrade` and `-s dist-upgrade`, and that the key name is right for apt 2.2.4 and, by reading the apt source or the 2.6.1 chroot if you can get one, 2.6.1). Update the spec text, the pin test and the golden fixtures.
- **R3 TMPDIR** (#59): `D/tmp` (mode 1777) and `TMPDIR=D/tmp`; D itself stays 0711 so `_apt` can traverse to it; verify with apt in the chroot as the `_apt` user that its temp files land in D/tmp (or drop the claim in comments and spec if apt does not honour it; prove which).
- **R4 CI invariance trees** gain `/var/log/apt` (#16); the CI leg gains two canary steps (#7, #18): a fragment `99osp-canary-splice` with `APT::Update::Post-In/**/voke-Success {"touch /var/lib/apt/periodic/osp-canary-splice";};` and a fragment `99osp-canary-include` with an `#include` of a second file holding a real `APT::Update::Post-Invoke-Success` hook that touches `/var/lib/apt/periodic/osp-canary-include`; the plan must NOT create either file, and `apt_conf_left_out` must name both fragments (reasons `not_simple`/`has_directive`); both are removed by traps afterwards (an undo that failed = INVALID RUN). V_STAMP stays for the real stamp when the box has one.
- **R5 runbook secrets** (#1-#4): the backup directory is created `mkdir -p -m 700` and `chmod 700` when it exists (in every block that writes in it); the archive is written in a subshell with `umask 077` around only that command (`( umask 077; tar ... )`), NOT a block-wide umask (dpkg and maintainer scripts must keep the default); an exec test (Linux, skipped without sh) proves directory 700 and archive 600 under umask 022.
- **R6 package-manager check** (#3, #47): never match the idle `unattended-upgrade-shutdown` helper or process names that merely start with `apt` (apt-cacher-ng); judge by the real transaction processes (comm `apt`, `apt-get`, `aptitude`, `dpkg` exactly, and the unattended-upgrade RUN by its args, not the shutdown helper) and, where it can be had without flock(1) (which does not see apt's fcntl locks), say that the lock is not tested by this line. A test lists the idle helper in the fake `ps` output and expects block 0 to pass.
- **R7 long blocks**: blocks 5 and 6 (and the whole runbook's prerequisites) require running inside `tmux`, `screen` or `systemd-run --scope`-style survival, or on a real console: the blocks themselves STOP unless `$TMUX` or `$STY` is set or the tty is a console device (`/dev/tty[0-9]*`, `/dev/hvc*`, `/dev/ttyS*`), with the exact words to start tmux or screen; say that ssh/smbd/cron restart during block 5.
- **R8 expiry and kernel** (#11): block 0 STOPs when the plan is older than 24 h (compare the epoch embedded in the text with `date +%s`); block 7 takes the target kernel from dpkg at run time (newest installed `linux-image-<digit>` version) and stops only if it equals `uname -r` while the plan expected a new kernel.
- **R9 block 7 barrier** (#10): add the design's barrier items the measured hop can support: systemd-resolved installed when it served as the resolver (resolv.conf pointing into /run/systemd/resolve) or active, a time daemon present, initrd of the new kernel over 5 MiB and `lsinitramfs` succeeds, the iptables alternative unchanged from the snapshot; each a STOP with the fix command; say in the block what is NOT checked.
- **R10 block 3** (#13, #15): STOP (with the restore command) when the re-simulation shows a kept-back section or a non-zero not-upgraded count; hash the written `.casaos-new` files with the plan's `hash_generated` canonical form (print it in the text) before the `mv`, and `sh -n` the restore script right after writing it; the restore script removes `done-sources`/`done-download`, moves `apt-orig` aside, and the resume map says so (#14).
- **R11 Suite undecided** (#9): in the exported `Suite()` only (the report's own `markDistro` is untouched), a non-official http/https host with no readable InRelease or Release for the suite, or a form that cannot be derived, is `decided=false` (Docker's host stays exempt); `RewriteSources` then refuses `sources_format` with the reason "run apt-get update first" in the detail; a test with the real decider and no lists.
- **R12 essential warning** (#8): apt's `WARNING: The following essential packages will be removed.` block (and its `This should NOT be done...` line and indented `name (due to other)` lines) is parsed, its names must be in REMOVED, they are marked essential; `removal_essential` blocked; test with apt's real text (reproduce it in the chroot by simulating the removal of an essential package, e.g. `apt-get -s remove login`, and keep the real output as a fixture).
- **R13 unknown room** (#19, #38, #32): `disk_short` data carries `unknown: true` when the free room could not be read (and `free` omitted); free room is read BEFORE the sandbox files are written (or the sandbox size is added back: choose the former), so the rows do not understate; the UI reads `unknown`.
- **R14 re-plan** (#61): fix the doc comment, behaviour stays (a new job drops the previous plan). **R15** (#70) nothing to fix (the first dispatch is the proof). **R16** (#71) declare the differences from the spec in the spec file's text.
- **R17 stop path** (#55, #63): `PostKillCasaOS` cancels the plan (`StopSystemOSPlan`) before `os.Exit(0)`; SIGINT is registered only when not ignored at start (#58); the stale-sandbox sweep requires: a directory (Lstat), owned by the core's euid, no group/other write bit, same device as its parent, name pattern, older than 10 minutes (#56); a failed removal is logged, retried once, and reported in the job state (#57); the job logs recovered panics and internal failures with their cause (#62); GET plan's identity gates share a singleflight and a transient failure is not reported as `identity_unsupported` (#64).
