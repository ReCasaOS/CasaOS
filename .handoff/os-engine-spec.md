## 1. Decision: build A, with these grafts and these drops
**Chosen: design A.** The unit runs the SAME nine reviewed blocks of `debian11to12Blocks` (as files derived from the generator, never from the manual text by string surgery), under a constant dash driver of about 75 lines that writes markers and unwinds before the point of no return. Go (the core) never runs inside the unit: it launches the unit, reduces markers and files into a state, settles, reboots on the owner's click, judges, and never calls apt or dpkg itself. The manual runbook stays the fallback and is the SAME artifact (same backup folder, same `done-*` files, same table "IF YOU STOPPED"); the golden of the manual text does NOT change in this rung.
Why not B or C, decided on the facts, not only on the judges: B puts about 5k lines of new root Go (a second implementation of the nine blocks, a pinned copy of the core binary, barrier auto-fixes: `update-initramfs`, `update-grub`, hold restore) on the point of no return before any QEMU proof, and its reducer row for a core launch marker with no unit has no age bound (a wedge). C's failure sentinel (`FAILED internal` with `restored -` read as clean) can report a clean machine while bookworm sources sit over bullseye packages, its driver has no `set -e` and its phase bodies are dots, and it leaves bookworm sources on a live bullseye box for up to 2 hours. None of the three has a fatal flaw that A lacks, so no fourth architecture is taken.
Facts checked against the code before deciding (all hold): (1) the golden has 157 `echo "STOP: ` lines, ALL of the one literal form `echo "STOP: `; 2 of them are inside the hash-pinned restore script that block 3 writes with a quoted heredoc, so 155 are the blocks' own; 99 distinct openings at 40 characters. (2) `restoreScript` repeats `set -eu` and a `STOP:` opening, so any string rewrite of block text that is not heredoc-aware breaks block 3's own `sha256` check. (3) `RewriteSources` with `From == To` refuses (`rewriteDistro`: `base == h.To` gives `sources_target`) and `checkTree` rejects a tree line "still of From"; `Firmware: true` would add `non-free-firmware` to bullseye lines: the refresh needs its own variant (ruling R6). (4) `maintenanceState` (`service/system_package_docker.go:79`) does `continue` when `systemctl show` fails: it FAILS OPEN when systemd does not answer. (5) `head()` stops EVERY block when ANY folder `/var/backups/casaos-os-upgrade-*` has `done-after`. (6) `restoreScript` refuses once `begun-upgrade` or `done-minimal` exists; block 5 writes `begun-upgrade` before `aptq upgrade` and takes it back only when it wrote it and `dpkgstate` is unchanged; block 7 writes `boot_id` just before `done-prereboot`, and its early path (`exit 0`, no `boot_id`) is the "restarted already" case. (7) The ids of the blocks are `verify timers snapshot sources download minimal full prereboot after`. (8) Under dash (tested here with the driver of section 6 and stub blocks: happy run, STOP before and after the point of no return, unwind, abort flag, bad list, tampered block, refresh, verify, rehearse): the EXIT trap is NOT inherited by a `( ... )` subshell, `set -e` death leaves class `unknown`, `exit 0` leaves no class. (9) The plan lives in memory in `osPlanState.plan` (with its tree, `Plan.Expired`), `ossupport` hop rows are constants `StateReport`.
Grafts taken (from the judges): from B and C, start refuses `manual_run_found`; unwind restores timers only when its own folder has `done-timers`; while systemd does not answer there is never a verdict and never a launch, and a launch marker with no unit is closed by an age bound; `failed(start)` after the point of no return keeps busy and is a click, never `failed(reversible)`; an unwind that was partial is `needs_attention`, busy; acknowledging a half-upgraded run needs a typed word; the busy file is read fail-closed by every reader; reducer property tests and an exhaustive kill-after-every-marker test; from C, block F and every recover launch stop the five apt units first and settle re-stops them after any boot while a run is open; a sources refresh variant, not the identity rewrite; a status log tail through the plan's sanitizer; a hand-off test under dash both ways; builder hooks, not literal rewrites, for the constants; the owner's beta 0 then beta 1; from B, `after_reboot_hint` in the status before the restart, a Docker HEAD failure after the restart is a warn finding, not a STOP; the reversible half can be exercised alone (the REHEARSAL of section 8, which is the small form of C's staged pause and of J2's "leg A first").
Dropped, with reasons: B's pinned copy of the core binary and any Go inside the unit (a unit that never needs the core cannot be hurt by a core update or restart); C's `stage`/`go` split and its 2 h pause (a second heavy click and a mixed-sources window; the rehearsal gives the reversible-first path without changing the approved journey); B's `immediate_configure_off` and C's identical omission is taken (the manual text does not have it: the engine adds nothing the manual does not know except the refresh, `sync` and `Use-Pty=0`); A's `hop_not_enabled` (it would stop PR 6 from ever starting a run); A's `no_backup` code (the readiness report run at start already holds `backup_age`); A's proposal to release the busy flag for auto update after 72 h; B's heartbeat staleness of the busy file; any automatic recover after the point of no return in this rung (ruling R4).

## 3. Architecture
```
 browser --HTTP--> core (Go, root, Restart=always)
                    | start/refresh: checks, run dir, files, busy flag, markers QUEUED RUN ATTEMPT, then systemd-run
                    v
        transient unit casaos-os-upgrade.service:  systemd-inhibit -> /bin/sh <run>/driver.sh   (nonce only in this process)
                    |  for each block id of the attempt's list:  sh <run>/blocks/<id>.sh   (stdout and stderr -> output.log)
                    |  one marker per event (markers file), unwind before the point of no return, NEVER reboots
                    v
 core: Reduce(markers + BK files + unit state + boot_id) -> State ; NextAction ; settle() every 30 s and at start
       POST /reboot -> internal power action -> machine restarts -> core sees a new boot_id -> verify unit (block 8) -> Go judge
```
Who runs what: shell in the unit, Go in the core, nothing else. The unit does not need the core binary: the driver and the blocks are files the core wrote, listed in `SHA256SUMS`, so a core that is updated, restarted or crashes does not touch a unit in flight. [M] the core, gateway and AppManagement answered throughout the hop; ssh, smbd and cron restart once at libc6.
**The unit command line** (`osUpgradeUnitArgs(a osrun.Attempt, dir string) ([]string, error)`, a closed allow-list: phase from the closed set, nonce `dockerpkg.ValidNonce`, `dir` = `/var/lib/casaos/os-upgrade/<uuid>` exactly, attempt 1 to 999; NO dollar sign anywhere in any argument, asserted, and passed through the port of systemd's expansion in `service/systemd_env_test.go`): `systemd-run --quiet --no-block --collect --unit=casaos-os-upgrade --property=Type=exec --setenv=PATH=/usr/sbin:/usr/bin:/sbin:/bin --setenv=LC_ALL=C --setenv=DEBIAN_FRONTEND=noninteractive --setenv=APT_LISTCHANGES_FRONTEND=none --setenv=NEEDRESTART_SUSPEND=1 --setenv=UCF_FORCE_CONFFOLD=1 --setenv=CASAOS_OSU_NONCE=<n> --setenv=CASAOS_OSU_DIR=<dir> --setenv=CASAOS_OSU_RUN=<run_id> --setenv=CASAOS_OSU_PHASE=<phase> --setenv=CASAOS_OSU_ATTEMPT=<n> -- systemd-inhibit --what=shutdown:sleep --who=casaos-os-upgrade --why=<fixed sentence> --mode=block /bin/sh <dir>/driver.sh`. The inhibitor is kept because the measured hop ran under it [M]; it is NOT a guard (root's reboot is not refused, measured). No `set -x` anywhere (block 3 holds the owner's sources, credentials included). The unit name is the constant `systemOSUpgradeUnit = "casaos-os-upgrade.service"`.
**Run directory** `/var/lib/casaos/os-upgrade/<run_id>/` (run_id a UUID; 0700 root; never executed by the core): `run.json` (identity, written once, 0600), `plan.json` (the plan WITH its tree, 0600: credentials), `driver.sh`, `blocks/<id>.sh`, `lists/<n>.list`, `SHA256SUMS` (driver.sh, bk-path and every blocks/*.sh), `manual-runbook.sh` (0600: `BuildRunbook(plan).Text`, typed words empty, persisted at start so the fallback survives the plan's 24 h and a core restart), `markers`, `output.log`, `facts-before.json`, `bk-path` (one line), `abort` (flag), `stop-class` (scratch, written by the blocks' trap), `barrier.json`, `verify.json`, `bk-aborted/` or `bk-done/` (the moved backup folder). Beside the run directories: `/var/lib/casaos/os-upgrade/current` (one line: the run id of the latest run; removed by `ack`), `/var/lib/casaos/os-upgrade/busy`, `/var/lib/casaos/os-upgrade/last-refresh` (RFC 3339, written by settle when it sees REFRESH_DONE), `/var/lib/casaos/os-upgrade/notified` (dedupe of alerts). Retention: the last 3 run directories (names are UUIDs, `run.json` present, no link followed, no glob). Deviation from design section 5: markers are a file of their own, apart from apt's output, which also never contains the nonce: a 128 KiB tail cannot drop a marker and apt's partial lines and carriage returns cannot be glued to one.
**Packages**: `pkg/osrun` (NEW, leaf: stdlib only; the vocabulary, `ParseMarkers`, `Reduce`, `NextAction`, `ActionsFor`, the timing constants, the driver text), `pkg/osverify` (NEW: `Facts`, `Judge`), `pkg/osplan` (gains `auto*.go`; imports `osrun` for the class names), `service/system_os_upgrade*.go`, `route/v1/system_os_upgrade.go`. `pkg/osrun` imports nothing of `osplan`, `osreadiness` or `service`.

## 4. Vocabulary (exact names; the UI, the CI report and the tests use these)
**Phases** (`osrun.Phases`): `refresh rehearse run recover verify unwind`. **Run kinds** (RUN marker): `refresh hop rehearsal`. **Block ids** (14, closed; the driver's `case` and `osrun.BlockIDs` are the same set, a test parses the driver text to prove it): `verify timers snapshot sources download minimal full prereboot after forward rcheck rsources rupgrade rdone`. `forward` is block F; `rcheck rsources rupgrade rdone` are the refresh blocks R0 to R3. Lists: run `verify timers snapshot sources download minimal full prereboot`; rehearse `verify timers snapshot sources download`; verify `after`; recover: `forward` (iff the first block without `done-<id>` among `minimal full prereboot` is `minimal` or `full`) then that block and the ones after it up to `prereboot`; unwind: the empty list; refresh `rcheck rsources rupgrade rdone`.
**Classes** (20, closed, `osrun.Classes`; the page has a sentence for each, a test checks it): `busy network apt_failed dpkg_broken unknown disk plan guard converge barrier_kernel barrier_initrd barrier_grub barrier_sshd barrier_resolver barrier_other identity tools unit integrity abort`. Behaviour by class (`osrun.ClassBehavior`): before the point of no return every class unwinds. After it: NO `resume` for `guard converge unit integrity plan` (`plan` that arrives with pnr 1, which happens because `checkSim`'s openings are the same text in blocks 3 and 5, is treated as `guard`); `resume` offered for all others; the later automatic waves (R4) are wave 1 `busy network`, wave 2 adds `apt_failed dpkg_broken unknown`; never automatic: `disk barrier_* guard converge identity tools unit integrity plan abort`.
**Class of an opening** (`osplan` `stopClasses`, one Go table, longest-prefix match on the text after `STOP: `; the builder derives every key from the golden with `grep` and assigns by these families): `busy`: a package manager is running, `$unit is still running`; `network`: apt-get update does not go through, the download did not go through, the download of the full upgrade; `apt_failed`: apt cannot work out ..., apt printed no summary line, the packages that apt lists as removed are not as many, the minimal upgrade failed, apt could not repair, the full upgrade failed again, a catch-up pass failed, apt-get upgrade failed before it changed any package; `dpkg_broken`: dpkg is not quiet, apt-get check finds, dpkg could not configure; `disk`: `/... needs N MB free`, `/boot has less`, `/boot/efi has less`, tar could not make the copy, `$BK/$f was not written`, the state of the timers could not be put; `plan`: the plan is older than 24 hours, the sources of apt are not the ones the plan was made from, the files written for apt are not the plan's, the files now in /etc/apt, apt would now keep packages back, apt would now remove a different set, apt would downgrade packages (the same text in blocks 3, 5 and 6: after the point of no return `plan` is treated as `guard`); `guard`: `$what would remove $name`; `converge`: apt still has something to do after the passes; `barrier_kernel`: dpkg has no linux-image, the plan installs a new kernel, `/boot/vmlinuz-`, `the kernel that runs now is not kept`, the machine runs the kernel (block 8); `barrier_initrd`: `/boot/initrd.img-`, lsinitramfs cannot open; `barrier_grub`: grub.cfg does not name, grub-pc has no disk, this machine starts with UEFI; `barrier_sshd`: sshd does not accept, the settings of sshd; `barrier_resolver`: systemd-resolved; `barrier_other`: no time daemon, the iptables alternative; `identity`: the hop is over, run this as root, this machine is not Debian 11/12, this machine is called, the machine has not been restarted, the sources of apt do not name bookworm, another plan of this machine, the upgrade has begun (a block for before it); `tools`: ss is not installed, curl is not installed, lsinitramfs is not there, ps did not answer; `integrity`: the block before this one did not end, a later block has ended, `$BK/apt-orig is there already`, `$BK/packages.tsv is not there`, `$BK/kernel is not there`, the restore script was damaged / is not the one of this text (the restore script's own two STOP lines are inside its heredoc, stay unclassified, and the unwind reads only its exit status); `unit`: the unit gate; `abort`: written by the driver only. Anything left with no class is `ErrAutoDrift` at generation.
**States** (23, closed, `osrun.States`): `idle refreshing reboot_first refreshed rehearsing rehearsed rehearsal_done running unwinding recovering awaiting_reboot rebooting reboot_stalled resuming verifying succeeded succeeded_with_findings failed interrupted stopped_at_waypoint needs_attention manual manual_done`. `failed` carries `reason` in a class name or `start`, `verify`, `half`, `interrupted_power`, `interrupted_killed`, and `reversible`. `interrupted` carries `cause` `power` or `killed`. `needs_attention` carries `reason` `systemd_silent`, `unwind_partial`, `run_damaged`. `running` carries the block. Busy (`State.Busy`): TRUE in every state except `idle refreshed rehearsal_done succeeded succeeded_with_findings manual_done` and a `failed` whose `pnr` is false (this includes `failed(start)` when nothing had begun, and excludes `failed(start)` with pnr). So busy is TRUE from the accepted POST through `refreshing rehearsing rehearsed running unwinding reboot_first awaiting_reboot rebooting reboot_stalled resuming verifying interrupted recovering stopped_at_waypoint needs_attention manual` and every `failed` with pnr (`failed(verify)`, `failed(half)`, `failed(start)` after the point of no return).
**Markers** (file `markers`, one `printf` one line, never touched by apt): grammar `CASAOS_OSU_<KIND> <nonce> <n> <fields...>`; `n` is the attempt number, `0` for run-level markers; fields match `[A-Za-z0-9_.:+~-]{1,64}`; times `2006-01-02T15:04:05Z`; a line is at most 256 bytes; the nonce is read from line 1 ONLY, every other line must carry it, anything else is ignored and counted in `status.ignored_markers`; the reader caps the file at 1 MiB. 21 kinds, the fields after `<n>`: `QUEUED <ts>` (core, line 1, n=0, written with O_EXCL); `RUN <run_id> <hop> <plan_id|-> <kind> <boot_id|->` (core, line 2); `ATTEMPT <phase> <from|-> <who auto|owner> <ts>` (core, written BEFORE `systemd-run`: a number is launched at most once); `START_FAILED <ts>` (core); `REBOOT_REQUESTED <ts>`, `REBOOT_FAILED <ts>` (core, n=0; the second cancels the first); `TAKEOVER <ts>`; `ACK <discard|acknowledge> <ts>`; `BOOT_SEEN <boot_id> <ts>` (core, once per boot while a run is open); driver: `UNIT_START <phase> <boot_id> <pid> <ts>`, `BLOCK_START <idx> <id> <ts>`, `BLOCK_DONE <idx> <id> <ts>`, `BLOCK_SKIPPED <idx> <id>`, `STOP <idx> <id> <rc> <class> <pnr 0|1> <ts>`, `UNWOUND <ok|partial> <ts>`, `REFRESH_DONE <yes|no> <why> <ts>`, `REHEARSAL_READY <ts>`, `REBOOT_PENDING <boot_id> <kernel> <ts>`, `REBOOT_NOT_NEEDED <kernel> <ts>`, `VERIFY_DONE <boot_id> <ts>`, `UNIT_END <ok|stopped> <ts>` (the driver's exit status is deliberately always 0). Boot ids are lower-case UUIDs, `-` when unreadable.
**Files that are the truth for the point of no return** (never the markers): `pnr = exists($BK/begun-upgrade) || exists($BK/done-minimal)`. The point of no return is therefore classified right even when the unit died before it wrote a marker.

## 6. The driver (`pkg/osrun/driver.go`, a Go RAW STRING constant `Driver`, not `go:embed`: a CRLF checkout breaks dash; `testdata/driver.golden` regenerated only by `-update`; no CR; this text was run under the dash of Git for Windows with stub blocks while writing this spec (it passes `dash -n` and `bash --posix -n`): happy run, STOP before and after the point of no return, unwind, abort flag before and after, a tampered block, a missing, empty and bad list, refresh with `refresh-reboot`, verify, rehearse, unwind phase)
```sh
#!/bin/sh
# casaos-os-upgrade driver. Runs the blocks that the core listed for ONE attempt, one marker per event, unwinds before the point of no return,
# never reboots. Constant text: nothing of the box is interpolated into it; everything it needs is in the environment of the unit or in files of
# the run directory that SHA256SUMS covers.
set -u
LC_ALL=C; export LC_ALL
PATH=/usr/sbin:/usr/bin:/sbin:/bin; export PATH
N=${CASAOS_OSU_NONCE:?}; unset CASAOS_OSU_NONCE
D=${CASAOS_OSU_DIR:?}; PH=${CASAOS_OSU_PHASE:?}; AT=${CASAOS_OSU_ATTEMPT:?}; : "${CASAOS_OSU_RUN:?}"
export CASAOS_OSU_DIR CASAOS_OSU_RUN CASAOS_OSU_ATTEMPT
case "$PH" in refresh|rehearse|run|recover|verify|unwind) ;; *) exit 0 ;; esac
exec >> "$D/output.log" 2>&1
ts() { date -u +%Y-%m-%dT%H:%M:%SZ; }
boot() { cat /proc/sys/kernel/random/boot_id; }
mark() { k=$1; shift; line="CASAOS_OSU_$k $N $AT"; for a in "$@"; do line="$line $a"; done; printf '%s\n' "$line" >> "$D/markers"; }
mark UNIT_START "$PH" "$(boot)" $$ "$(ts)"
end() { mark UNIT_END "$1" "$(ts)"; exit 0; }
cd "$D" || end stopped
BK=$(cat "$D/bk-path" 2> /dev/null || true)
case "$BK" in /var/backups/casaos-os-upgrade-*) ;; *) BK=/nonexistent ;; esac
sha256sum -c --quiet SHA256SUMS > /dev/null 2>&1 && [ "$BK" != /nonexistent ] || { mark STOP 0 driver 1 integrity 0 "$(ts)"; end stopped; }
pnr() { [ -e "$BK/begun-upgrade" ] || [ -e "$BK/done-minimal" ]; }
unwind() {   # before the point of no return only: the steps of the manual table, in the order of the manual table
  pnr && return 1
  ok=ok
  if [ -d "$BK/apt-orig" ]; then
    if [ -f "$BK/restore-sources.sh" ]; then sh "$BK/restore-sources.sh" < /dev/null || ok=partial; else ok=partial; fi
  fi
  TS=/var/backups/casaos-os-upgrade-timers.state
  if [ -e "$BK/done-timers" ] && [ -s "$TS" ]; then
    back=ok
    for u in $(awk '$2 == "active" { print $1 }' "$TS"); do systemctl start "$u" || back=partial; done
    [ "$back" = ok ] && rm -f "$TS" || ok=partial
  fi
  if [ "$PH" = refresh ] && [ -f "$D/blocks/forward.sh" ] && [ -n "$(dpkg --audit 2>&1)" ]; then sh "$D/blocks/forward.sh" < /dev/null || ok=partial; fi
  if [ -d "$BK" ]; then mv "$BK" "$D/bk-aborted" || ok=partial; fi
  mark UNWOUND "$ok" "$(ts)"
}
halt() {   # a block ended with a status that is not 0 (or the owner asked to stop): $1 index, $2 id, $3 status, $4 class
  p=0; pnr && p=1
  mark STOP "$1" "$2" "$3" "$4" "$p" "$(ts)"
  [ "$p" = 1 ] || [ "$PH" = verify ] || unwind < /dev/null
  end stopped
}
[ -f "$D/lists/$AT.list" ] || halt 0 list 1 integrity
want=$(( $(wc -l < "$D/lists/$AT.list") ))
[ "$PH" = unwind ] || [ "$want" -gt 0 ] || halt 0 list 1 integrity
idx=0
while read -r id; do
  idx=$((idx + 1))
  case "$id" in verify|timers|snapshot|sources|download|minimal|full|prereboot|after|forward|rcheck|rsources|rupgrade|rdone) ;; *) halt "$idx" list 1 integrity ;; esac
  if [ -e "$BK/done-$id" ]; then mark BLOCK_SKIPPED "$idx" "$id"; continue; fi
  rm -f "$D/stop-class"
  mark BLOCK_START "$idx" "$id" "$(ts)"
  # the owner's abort is read AFTER the start of the block is written: the core writes abort, then reads the markers; one of the two sees the other
  if [ -e "$D/abort" ] && ! pnr; then halt "$idx" "$id" 0 abort; fi
  [ "$id" != minimal ] || sync
  rc=0; sh "$D/blocks/$id.sh" < /dev/null || rc=$?   # stdin is the list file here: a child must never read it
  [ "$rc" -ne 0 ] || { mark BLOCK_DONE "$idx" "$id" "$(ts)"; continue; }
  cls=$(cat "$D/stop-class" 2> /dev/null || true); case "$cls" in ''|*[!a-z_]*) cls=unknown ;; esac
  halt "$idx" "$id" "$rc" "$cls"
done < "$D/lists/$AT.list"
[ "$idx" -eq "$want" ] || halt "$idx" list 1 integrity
case "$PH" in   # what the phase ends with
  refresh) want=no; why=none; read -r want why < "$BK/refresh-reboot" 2> /dev/null || true
           case "$want" in yes|no) ;; *) want=no ;; esac; case "$why" in ''|*[!A-Za-z0-9_.-]*) why=none ;; esac
           mark REFRESH_DONE "$want" "$why" "$(ts)"; [ ! -d "$BK" ] || mv "$BK" "$D/bk-done" || true ;;
  rehearse) mark REHEARSAL_READY "$(ts)" ;;
  run|recover)
           kernel=$(cat "$BK/kernel" 2> /dev/null || true); case "$kernel" in ''|*[!A-Za-z0-9_.+~:-]*) kernel=unknown ;; esac
           if [ -s "$BK/boot_id" ]; then mark REBOOT_PENDING "$(cat "$BK/boot_id")" "$kernel" "$(ts)"; else mark REBOOT_NOT_NEEDED "$kernel" "$(ts)"; fi ;;
  verify) mark VERIFY_DONE "$(boot)" "$(ts)" ;;
  unwind) unwind < /dev/null || halt 0 unwind 1 guard ;;
esac
end ok
```
Properties the text must keep (each has a test, section 14): no pipeline with an early exit (no SIGPIPE 141), no `trap` in the driver (a stop kills the unit; the reducer reads a lost unit from the files), no reboot or shutdown command, no job control, stdin of every child is `/dev/null`, no `set -x`, the nonce is NOT in any child's environment (a stub `apt-get` prints `env`), every marker is one `printf` and parses with `ParseMarkers` and `Reduce`, the exit status is always 0, `sync` runs before block `minimal`, the unwind of a pre-pnr STOP restores the sources (the restore script runs), the timers ONLY when `done-timers` is there, and moves the folder to `bk-aborted`; `halt` with pnr 1 never unwinds; the abort flag is read after `BLOCK_START` and ignored once pnr is true; the list ids equal `osrun.BlockIDs`. The `STOP ... integrity` for a missing or malformed list uses id `list`, which is the one id that is not a block (the reducer accepts `driver`, `list`, `unwind` as non-block ids of a STOP).
`SHA256SUMS` holds the lines for `driver.sh`, `bk-path` and `blocks/<id>.sh` of every block the run may use (hop, rehearse, recover, verify, unwind: all nine blocks and `forward`; refresh runs: the four R blocks and `forward`); written LAST by the core, after the files, and re-hashed by the core before EVERY launch (`integrity` STOP otherwise: never automatic). `lists/<n>.list` is written per attempt and is deliberately not in it: the driver validates every id against its own `case`.

## 7. The reducer (`pkg/osrun`: `marker.go`, `reduce.go`, `action.go`; pure: no clock, no file, no systemd, no network)
```go
func ParseMarkers(r io.Reader) (nonce string, ms []Marker, ignored int, err error)   // reads at most MarkersMax; never panics on any bytes
```

"L" is the attempt with the highest `n`. `M` is the latest RESULT marker of the whole run (`REFRESH_DONE`, `REHEARSAL_READY`, `REBOOT_PENDING`, `REBOOT_NOT_NEEDED`, `VERIFY_DONE`, whatever attempt wrote it): rules 11 to 15 read M, so that `resuming` stays the answer in the seconds between the ATTEMPT of a verify launch and its UNIT_START. `pnr` always comes from `Files`. `HalfUpgraded = pnr && !DonePrereboot`. `Reversible = !pnr`. First matching rule wins:
| # | Condition | State |
|---|---|---|
| 1 | no valid line 1, or no RUN line | `idle` |
| 2 | an ACK marker | `idle` (closed) |
| 3 | a TAKEOVER marker | `manual`; `manual_done` when `DoneAfter`. No action is ever launched (the engine stops acting; busy stays until `done-after` or an ack) |
| 4 | L has no UNIT_END, `!Unit.Answered`, and `Now - LastActivity >= SystemdSilence` (30 min) | `needs_attention(systemd_silent)`, busy. No verdict, no launch, ever, while systemd does not answer |
| 5 | L has no UNIT_END and the unit is effectively active: `Unit.Active`, or `!Unit.Answered` with activity inside `SystemdSilence`, or L has UNIT_START and the unit is inactive but `Now - LastActivity < GraceQuiet` (30 s: systemd can say "gone" before the last line lands) | by `L.phase`: `refreshing rehearsing running(block) recovering verifying unwinding`. `block` = the last BLOCK_START without BLOCK_DONE/BLOCK_SKIPPED |

**boot_id rules.** (a) Three ids are recorded: in QUEUED/RUN, in every UNIT_START, in REBOOT_PENDING (read from `BK/boot_id`, which block 7 writes just before it ends). (b) "The machine restarted" is only ever `current != recorded`, whoever restarted it: the button, the console, a power cut, the hypervisor; the core never assumes who. (c) A boot id that cannot be read is unknown: nothing is inferred, the state stays, `BootUnknown`. (d) `rebooting` and `reboot_stalled` are not terminal: only a different id leaves them; stalled adds a reminder and keeps the button. (e) A second restart before verify ended makes the verify attempt `interrupted`; it is launched again (`MaxVerifyAttempts` 3): block 8 is repeatable and the file `done-after` wins over any marker. (f) A disk-only snapshot restore gives a new boot id and files of the same moment: consistent, only earlier.

| State | Action |
|---|---|

**Interruptions, by kind of event** (each cell is a row of the reducer and NextAction tests):
| Event | Before the point of no return (refresh, blocks 0 to 4, block 5 before its marker) | After it (block 5 from the marker, 6, 7) | awaiting_reboot / rebooting | verify |
|---|---|---|---|---|

Blocks 0, 1, 2: timers stopped (back at boot), BK folder: unwind, BK to `bk-aborted`. Block 3: `apt-orig` whole or absent, maybe `*.casaos-new`, sources maybe replaced: restore script removes the `.casaos-new` files and restores. Block 4: the same plus downloads in the cache. Block 5 before the marker: nothing changed: as block 4. Block 5 marker written, no dpkg write yet: `interrupted`, pnr 1: `resume` runs F (finds nothing) then block 5 again (`fresh=no`). Block 5 or 6 in dpkg: half-unpacked packages, `dpkg/updates` journal, Debian 11 and 12 mixed: `resume` = F then the block again. Block 6 convergence: everything installed, `done-full` missing: `resume`, block 6 ends at once. After `done-full`, before block 7: `resume` runs block 7 (no F). Block 7 ended, REBOOT_PENDING not written: rule 13 from the files. Shutdown in progress: no unit. Boot before verify: `resuming`. Block 8: `interrupted`, `DoneAfter` false, verify again.

## 8. settle(), rehearsal, actions, abort (`service/system_os_upgrade_settle.go`)
`settle` runs at core start (after READY, not in `init`), every `SettleEvery` (30 s) while a run is open or the busy file exists, and after every route that changes a run. One goroutine, `osUpgradeMu` held ONLY to append a marker and call `systemd-run`, never across a wait, never by a status read. Steps: (1) reduce; recompute the busy file (section 10); an `idle` state with no `current` removes a stale busy file. (2) on a boot id that is neither the RUN line's nor in a BOOT_SEEN marker, while a run is open and the boot id is readable: append BOOT_SEEN and stop the five apt units (R9). (3) `NextAction` and exactly ONE action per tick. (4) `resuming`: the readiness wait is non-blocking (each tick asks `systemctl is-system-running` without `--wait`, `docker.service`, a default route; the deadline is `ResumeWait` from BOOT_SEEN; after it verify starts anyway). (5) `awaiting_reboot`: the Go barrier (read-only: the readiness checks `fstab_unresolved`, `fstab_network`, `network_names` run by code through `Check.Run`, NOT through `osreadiness.Run` whose identity gates would read `/etc/os-release`, which already says bookworm; NOT `findmnt --verify`: the readiness allow-list refuses it on purpose, it probes devices through libblkid and is not a read, and `fstab_network` is decided from the parsed `/etc/fstab` alone) into `barrier.json`; red means the reboot button is not offered (`actions` lacks `reboot`, `barrier.checks` says which); settle reruns it each tick, so "check again" needs no route. (6) alerts (section 11). (7) keep the last 3 run directories. Every action is logged with the run id and attempt. `settle` NEVER runs apt, dpkg or `resume` by itself in PR 4.
**Launching an attempt** (`launchAttempt(phase, from, who)`): under `osUpgradeMu`: re-hash `SHA256SUMS` (a mismatch is START_FAILED plus `needs_attention(run_damaged)`), compute the list from the FILES (recover: the first block without `done-<id>` among `minimal full prereboot`; `forward` first iff it is `minimal` or `full`), write `lists/<n>.list`, append ATTEMPT, call `systemd-run` with `osUpgradeUnitArgs`; on error append START_FAILED. A number is never launched twice. A crash between ATTEMPT and `systemd-run` leaves an ATTEMPT with no UNIT_START: rule 6 closes it after 30 s.
**Rehearsal** (R5): `POST /start {"rehearsal":true,...}` makes a run of kind `rehearsal` whose first attempt is phase `rehearse` (list `verify timers snapshot sources download`). It ends REHEARSAL_READY and the state `rehearsed`: the machine holds Debian 12's sources for at most `RehearsalTTL` (30 min), busy (the packages window, Docker update, auto update and AppManagement backups refuse meanwhile), a banner says "run no apt by hand". `ack discard`, the TTL, or a different boot id launches the `unwind` attempt, then `rehearsal_done` (not busy; `ack acknowledge` closes it). The plan stays good afterwards (the restore is byte-identical, so `sources_changed` does not fire): the owner then makes a real `start` with the same plan. A rehearsal never reaches block 5.
**Takeover** (`ack manual`): valid only with no unit active; appends TAKEOVER; from then on the reducer says `manual` and nothing is launched. The status carries `manual {blocks_done, next_block, pnr, bk_path}` from the `done-*` files and `GET /runbook?run=current` returns `manual-runbook.sh`. `manual_done` when `done-after` is there.
**Abort protocol** (R8). `POST /abort` valid in `refreshing`, `rehearsing`, `running` while pnr is false and the last BLOCK_START is block 0 to 4 (or the unit has not started its first block). Sequence: create `<run dir>/abort` with O_EXCL (an existing one means an abort is already under way: 202 with the status); read the markers and the files; if refused, remove the flag and answer 409 `not_abortable {reason: point_of_no_return | past_block | not_running}`; else `systemctl stop casaos-os-upgrade.service` (returns when the unit is gone), then settle's `unwind` follows (state `unwinding`, then `failed(abort)` reversible; a rehearsal aborted before REHEARSAL_READY ends the same way). The driver's side is in section 6; the interleaving test is T4.
**Actions table** (`ActionsFor`: the server decides, the UI shows exactly these, and the flag does not change them: R3): `refreshing rehearsing running(pre-pnr)`: `abort`; `running(post-pnr) unwinding recovering resuming verifying rebooting`: none; `reboot_first`: `reboot acknowledge`; `refreshed rehearsal_done succeeded succeeded_with_findings failed(reversible)`: `acknowledge` (and `discard` for a failed one with a live plan: it drops the plan); `rehearsed`: `discard`; `awaiting_reboot reboot_stalled`: `reboot` (only when the barrier is green) and `takeover`; `interrupted(pnr) stopped_at_waypoint`: `resume` (when class behaviour allows), `takeover`, `acknowledge` (typed word); `failed(start)` with pnr: `resume takeover`; `failed(verify)`: `resume takeover acknowledge`; `needs_attention`: `takeover acknowledge` (typed word when half-upgraded); `manual`: `acknowledge` (typed word when half-upgraded: the owner gives up the manual road); `manual_done`: `acknowledge`; `interrupted(no pnr)` and `unwinding`: none (the unwind is automatic).

## 12. Refresh: the old release brought to its last state (S8; `auto_refresh.go`, `HopSpec.ForRefresh`)
A refresh is a run of kind `refresh`: phase `refresh`, list `rcheck rsources rupgrade rdone`, folder `/var/backups/casaos-os-upgrade-refresh-<run_id>`, no plan, no point of no return. `RefreshInputs{Hop HopSpec, Rewritten *Rewritten, AcceptReleaseInfo bool, RunID, Hostname string}` (the tree comes from `RewriteSources(ctx, hop.ForRefresh(), files, decider)`, run by the core at POST time with the same decider and the same files as the plan; undecided is `source_unrecognized`).
- **rcheck (R0)**: root; the box is still Debian 11; `dpkg --audit` quiet; `aptq check`; no package manager (`busyCheck`); no other plan's folder with `begun-upgrade` or `apt-orig` (`otherPlans()`); coarse floors (1.5 GB archives, 2 GB `/`: there is no plan); kernels written to `kernels-before.txt`; the timers state written exactly as block 1 writes it (factor the state-file code of block 1 into one function used by both; the manual output stays byte-identical) and the units stopped; writes `done-timers` then `done-rcheck`.
- **rsources (R1)**: the restore script written and hash-checked as block 3 does, `apt-orig.new` renamed to `apt-orig`, the tree written under `.casaos-new`, read back and hash-compared (`treeFiles(c)`), `expected-removed.txt` written EMPTY, `aptq update --error-on=any` (plus `--allow-releaseinfo-change` iff accepted). Third-party files and lines are paused by the tree, as in the plan; backports are kept (the measured refresh kept them).
- **rupgrade (R2)**: `aptq -s dist-upgrade -o APT::Get::Always-Include-Phased-Updates=true > resim.txt`, `checkSim`, `guard_removals`, and ZERO removals (any removal is STOP `plan`: "the current release wants to remove NAME: use the manual path or the packages window"); `--download-only dist-upgrade`; `dist-upgrade` with the same option; on failure the same repair ladder as block 6 (factor it into one function used by both blocks, manual output byte-identical); `dpkg --audit` quiet; `aptq check`.
- **rdone (R3)**: `sh restore-sources.sh` (sources back, hash equal to R1's own `HashCurrent`, which a test checks; it ends with `apt-get update`), timers back as block 8 does, `refresh-reboot` written as one line: `yes reboot-required` when `/var/run/reboot-required` exists, `yes kernel` when a `linux-image-*` package is new or has another version than in `kernels-before.txt`, else `no none`; `done-rdone`.
- the driver turns it into REFRESH_DONE and moves the folder to `bk-done`; `reboot_first` is the state while the box wants a restart on the same boot. The plan is made AFTER the refresh; `start` refuses a plan older than the last refresh.
- Tests: the refresh rewrite (`ForRefresh`: a distribution line kept verbatim, `non-free-firmware` NOT added, backports kept, non-distribution paused, `sources_target`/`sources_alias` still refuse, `checkTree` accepts, idempotence on its own output); the R blocks under dash with stubs on both texts' common fixtures; the refresh golden; and in the Debian 11 chroot with real apt 2.2.4 (the `parse_chroot_test.go` style): `RewriteSources` refresh output accepted by apt, the real `apt-get -s dist-upgrade` text through `removed_of` and `checkSim`, the restore script on real files. Mutation checks: zero-removals rule removed; `ForRefresh` made the identity-with-firmware rewrite (a test sees `non-free-firmware` appear); the hash comparison after R3 removed; `done-timers` not written (the unwind then leaves the timers stopped: a test sees it).
- Slice S8 may ship as its own PR if S1 to S7's review budget is exceeded: nothing else depends on it.

## 13. The Go judge (`pkg/osverify`, S4; read-only, through the readiness `Probe`)
`Facts(ctx, p Probe) Facts` is ONE function that takes the facts BEFORE (at start, `facts-before.json`) and AFTER (at judge time): Samba users (the count of `pdbedit -L`; an absent tool is unknown, never an error), mergerfs mounts (the `fuse.mergerfs` lines of `/proc/mounts`, read through `ReadFile`), the default route (`/proc/net/route`, through `ReadFile`), whether the resolver answers a name (Go's resolver, 5 s), Docker's version and engine id. Every command goes through the readiness allow-list (`pkg/osreadiness/allowlist.go`, with its boundary tests), never a second runner; the only new shape is `pdbedit` with exactly `-L`, and `findmnt --verify` stays refused (it probes devices). What block 2 already records in `$BK` is read from there, not re-taken: `listening.txt`, `failed-units.txt`, `casaos-units.txt`, `containers.txt`, `holds.txt`, `dpkg-files.txt`, `kernel`, `docker-source-note`. `Judge(before, after Facts, bk BKFiles) []Finding`, `Finding{Code, Severity error|warn|info, Arg}`, closed list: ERROR `kernel_unexpected` (running kernel differs from `$BK/kernel`; block 8 already stops on it, the judge confirms), `casaos_unit_down` (active before, not now), `docker_down`, `mounts_missing` (a mergerfs pool that was mounted is not: names the apps; a container with a restart policy would write into an empty mount point), `dpkg_not_quiet`, `system_not_ready` (never `running` or `degraded` before the deadline); WARN `units_failed_new`, `ports_missing`, `samba_users_changed`, `route_missing`, `dns_missing`, `docker_version_changed`, `docker_source_unreachable`, `container_not_returned {container,policy}` (policy `no` is neutral: `dockerpkg.NotReturned`); INFO `docker_source_not_published`, `docker_source_paused`, `dpkg_dist_new` (files since block 2), `sources_left_paused`. `succeeded` when there is no error and no warn (info findings are listed and never change the state: a Docker box normally keeps `docker_source_paused`), `succeeded_with_findings` when there is at least one warn and no error, `failed(verify)` when an error exists. Nothing is repaired automatically in this PR (no restart of a unit, no install, no start of a container). `verify.json` is written atomically and idempotently by settle; the judge never blocks a request.

**Cross-cutting tests (each is named in a slice's definition of done).** (T1) **Marker hostility**: forged nonce, a marker inside noise, a partial last line, CRLF, NUL, 257-byte lines, unknown kind, wrong field count or regex, duplicate terminals, a wrong attempt number, a 2 MiB file (read capped at 1 MiB), a marker after ACK; `ParseMarkers` never panics (a fuzz target with a committed corpus runs in the normal test). (T2) **Reducer properties** (fixed seed plus the corpus, at least 2000 generated valid sequences each): P1 appending any marker after a terminal state (an ACK excepted) never changes the state; P2 any prefix of a valid marker sequence reduces to a state that the full sequence's transition graph allows; P3 `Reduce` is pure (same input, same output); P4 `Busy` is true in every state with `pnr` true and no `done-after`; P5 `Reversible == !PNR` in every state. (T3) **Exhaustive crash test** (Linux, dash): run the real auto blocks with a stub box through the real driver; for EVERY marker line k of the happy-path sequence, of the sequence with a STOP at each block, and of the sequence with the abort flag at each block, kill the driver with SIGKILL right after line k (a test-only transformation of the driver text appends `[ "$(wc -l < "$D/markers")" -lt K ] || kill -9 $$` after the `mark` function's `printf`, asserted to apply exactly once), then for each BK file combination that block can leave (including "the BK file of the step was written, the marker was not") run `Reduce` and `NextAction`, execute the chosen action (the `unwind` phase through the driver, with the stub `systemctl`/restore script), and assert: sources restored iff pnr was false; `begun-upgrade` never written twice; the timers file restored only with `done-timers`; the run ends in `failed` reversible or `needs_attention`, never in a state the files forbid; `UNWOUND partial` is never `failed`; busy is consistent after every action. (T4) **Abort interleavings**: for the abort sequence of section 8 and the driver loop, every interleaving of the two ordered pairs {core writes flag, then core reads markers} and {driver writes BLOCK_START, then driver reads flag} (the 6 valid orders, run over a shared fake directory) ends either with the core refusing and the block running, or with the driver stopping, and NEVER with `systemctl stop` while block `minimal` has started. (T5) **Hand-off under dash, both ways**: (a) after each driver block of a happy run on a stub box, the NEXT block of the MANUAL text (typed words set) passes its `head()` gate on the same box; after a stubbed failure at each block the row of the manual table "IF YOU STOPPED" applies (the files the manual says); (b) after each manual block run by the existing exec harness, a driver started with the list of the remaining blocks continues (skips the `done-*` ones) and ends the same. (T6) **Unit gate and nonce**: an auto block run outside the unit STOPs `unit`; a stub `apt-get` that prints `env` shows no `CASAOS_OSU_NONCE` and not the nonce's value; a stub package that prints a line shaped like a marker into `output.log` does not reach `markers`. (T7) **Allow-lists**: `osUpgradeUnitArgs` accepts exactly the shapes of section 3 and refuses a wrong phase, an invalid nonce, a dir that is not `/var/lib/casaos/os-upgrade/<uuid>`, an extra argument, a `$`; the ids of the driver's `case`, `osrun.BlockIDs`, the lists the core writes and `SHA256SUMS`'s coverage are one set (a test parses the driver text). (T8) **Flag off = product unchanged**: with the flag file absent every POST but `beta` answers `beta_off` (and `reboot resume abort ack` answer `no_run` when there is no run), `GET /status` says `beta_enabled:false`, `maintenanceState` answers as before when no busy file and no unit exist (the existing readiness and Docker update tests stay green untouched). (T9) **Windows**: all of `pkg/osrun`, `pkg/osverify`, the Go parts of `service` and `route` run natively; the tests that start a shell skip under `-short` with the reason and when `sh` is missing; any helper touched from several goroutines has its lock (no `-race` here).
**Mutation discipline** (the plan's "broken then seen failing"): every guard of a slice's list is broken on purpose, a NAMED test is seen failing, the break is reverted; the report lists each. The lists are in section 15.
