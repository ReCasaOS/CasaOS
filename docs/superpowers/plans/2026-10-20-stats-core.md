# Statistiques: plan du cœur (machine `host` + catégorie `resources` du hub) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The core measures the machine every 5 s into the shared `pkg/stats` store (item `host`, routes under `/v1/sys/stats`), evaluates its own `cpu_high` / `mem_high` rules, and its alert hub learns a `resources` category fed by `resource:alert-firing` / `resource:alert-resolved` from AppManagement, virt and the core itself.

**Architecture:** A new package `pkg/hoststats` holds a pure `Collector` (raw readings -> `stats.Sample`), a `Sampler` (tick -> `Store.Record`; a written minute -> `Evaluator.OnMinute` through `Store.SetOnMinute`) and a `SystemSource` (gopsutil + LocalStorage). `pkg/alerts` gains the category, the two events (parsed by a new `fromResource`), and a bus subscription per bus source. Existing `GET /v1/sys/utilization` and the 5 s `casaos:system:utilization` push are not touched.

**Tech Stack:** Go 1.26, `github.com/ReCasaOS/CasaOS-Common/pkg/stats` (tag v0.4.28), gopsutil v3.23.2 (already in go.mod), echo v4, gorilla/websocket (hub tests), the message bus (`codegen/message_bus`, generated by `go generate`, gitignored).

## Global Constraints

- Cadence: one measure every 5 s; history is the Common store's (minute avg/min/max, 7 days, ring file, atomic). The core only calls `Record`.
- Budget: this service's sampling stays at or under 0.5 % of one core (its own budget, not summed with AppManagement's or virt's); this package is held to **under 10 ms of CPU per tick** (0.2 % of a core) and measured (Task 7).
- Identity of the machine item: `host`. Store dir: `/var/lib/casaos/stats/core`.
- Series keys exactly as the contract: `cpu/total`, `cpu/vcpus`, `memory/rss|cache|swap|limit`, `network/rx|tx|dropped:<interface>`, `disk/read|write|iops_read|iops_write`, `fs/free_percent:<mount point>`, `alert/cpu_high`, `alert/mem_high`. Never `restarts/*`, `health/*`, `pids/*`, `cpu/user|system|iowait|throttled` for the host. A key absent means no data, never 0.
- Defaults come from `stats.DefaultRules()` (cpu_high 90 % 10 min, mem_high 90 % 5 min). Alerts on the host's free disk space are NOT added: the hub's `disks` category already covers them (spec).
- The 5 s push `route.SendAllHardwareStatusBySocket` and `GET /v1/sys/utilization` stay byte-identical in behaviour. Consequence: the sampler never calls `cpu.Percent` (gopsutil keeps one global "last times" in `lastCPUPercent`, `cpu/cpu.go:56-193`; a second caller would halve the widget's window). It reads `cpu.Times(false)` and does its own delta.
- Routes behind the token (inside `v1SysGroup`, `route/v1.go:103`); no content from a container or VM in an error message. Text from services is text, never HTML (UI concern).
- Alert hub: category `resources` on by default; a config file without the key keeps working; sentences are plain and carry nothing sensitive (`plain()` of `bus.go:248`); dedupe 6 h and "resolved only if firing was sent" are the hub's existing rules (`alerts.go:184-244`), not re-implemented.
- No test uses the real clock for logic (`stats.Clock` / `Hub.Now` injected). Commits: no `Co-Authored-By`, no "Generated with", nothing about reviews or the owner (CI `no-ai-attribution.yml` checks).
- Tests: `go test -race` clean (goreleaser's hook runs `go test -race -v ./...`). `pkg/alerts`, `pkg/hoststats` (except the cost test) run on the Windows host. `route/...`, `service/...`, `main` and the cost test (`/proc`, `/sys`) run in WSL (`wsl`, any user; root not needed). Run `go generate` once first (needs network, fetches the bus openapi at the version pinned in `main.go:2`).

## Review Focus

Failure modes the spec implies; each has its test in the named task.
1. A counter that goes backwards (interface unplugged, `/proc/diskstats` reset), a clock that does not advance, the very first reading after a start: the rate must be absent, never 0 and never a huge number (Task 5).
2. LocalStorage unreachable or answering garbage: the `fs/*` series are absent but every other series is still recorded and nothing panics (Tasks 5, 6).
3. The core restarts in the middle of a "10 minutes in a row" count: no second `firing`, no forgotten alert (Task 6).
4. Hub input that is wrong or hostile: `resources` off then a `resolved`, the same key twice, an unknown situation or kind, a missing `item`, a name with a newline or 10 000 characters (Task 3).
5. A Docker update or an OS upgrade (both mute container events, `main.go:154-159`) makes the box busy for minutes: `cpu_high`/`mem_high` are dropped while muted, `vm_crashed` is not (Task 3).
6. A failed `Read` (a gap) while an alert is firing resolves nothing, and the high minutes after it do not fire a second time (Task 6 `TestAFailingReadDoesNotResolveAFiringAlert`). The host never stops being an item, so there is no `Resolve` case here.
7. The evaluator's files in `/var/lib/casaos/stats/core` (`alerts.json`, `alerts.json.tmp`) survive the Store's `Open` and `Sweep` (Task 6 `TestTheStoreLeavesTheEvaluatorsFilesAlone`).

## Extensions (to the contract; the other plans must follow)

- **E1** `minutes` (the rule's window, string of an integer) is a property of `resource:alert-*` in the contract (section 3); AppManagement, virt and the core send it. Absent, the hub sentence omits the duration.
- **E2** Hub subscriptions are per **bus SourceID** (the bus filters by `/event/{source_id}`, `CasaOS-MessageBus/route/api_route_event.go:SubscribeEventWS`). The contract's property `source` (`app_management`, `virt_management`, `core`) is informational and is not used to route. Verified: AppManagement's SourceID is `app-management` (`CasaOS-AppManagement/common/constants.go:4`), where it also registers `app:container-*` (`common/message.go:458-495`). The virt module's SourceID is **not verifiable here** (its repo is not in the tree): Task 4 makes it one constant and a verification step.
- **E3** The core's own events are published under SourceID `casaos` (`common.SERVICENAME`), registered in `common/message.go` (the core's place; `app:container-*` are registered by AppManagement, not the core), and handed to the hub **in-process** (not through a subscription, to avoid a double delivery).
- **E4** For the host the core also writes `memory/limit` (= total RAM, so the page draws the limit line) and `cpu/vcpus` (= logical CPUs).
- **E5** `/v1/sys/stats*` answers inside the core's usual envelope `model.Result{success,message,data}` (every `/v1` route and `route/v1/alerts.go` do): `data` is exactly the contract body. Errors are the HTTP status plus `message` = the contract code (`unknown_item`, `bad_range`, `bad_rules`, `stats_unavailable`). The dashboard must unwrap `data` for the core only.
- **E6** Hub sentences are English, like every sentence of the hub (`bus.go:206-223`), not the French example of the contract: `<name>: CPU at 93 % for 10 min.`; the host's `name` is the machine's hostname (fallback `Machine`), the same value as the item name served by `/v1/sys/stats`.
- **E7** Properties are plain strings. The core must not publish through `Notify().SendNotify` (it JSON-quotes every value, `service/notify.go:55-59`); Task 6 publishes with `MessageBus().PublishEventWithResponse` directly.
- **E8** Needs from Common (all in the contract; verified in Task 1, else STOP and ask the Common plan): `Store.SetOnMinute` is the single wiring and fires after minute M is written (so `OnMinute(item, M)` can read it); `Point`, `SeriesData` and `Result` marshal with the contract's JSON tags; `Open` creates `dir` and deletes only `*.ring.tmp`; `SetRules` returns `*stats.RuleError`.

### Task 5: Collector: raw readings to a `stats.Sample`

**Files:** Create `pkg/hoststats/collector.go`, `pkg/hoststats/collector_test.go`.

**Interfaces:**
- Produces (all in package `hoststats`):
  ```go
  const Item = "host"
  type CPUTimes struct{ Busy, Total float64 }                // seconds, cumulative, gopsutil's own busy (total - guest - idle - iowait)
  type NetCounters struct{ RxBytes, TxBytes, Dropped uint64 } // Dropped = Dropin + Dropout, cumulative
  type DiskCounters struct{ ReadBytes, WriteBytes, ReadOps, WriteOps uint64 }
  type Volume struct{ MountPoint string; Size, Used uint64 }
  type Reading struct {
      At      time.Time
      CPU     CPUTimes
      Cores   int                    // logical CPUs
      MemTotal, MemUsed, MemCached, SwapUsed uint64
      Nets    map[string]NetCounters // physical interfaces only
      Disk    *DiskCounters          // nil: unreadable
      Volumes []Volume               // nil: unreadable or none
  }
  type Collector struct{ /* previous Reading */ }
  func (c *Collector) Sample(r Reading) stats.Sample
  func realVolume(v Volume) bool           // the exclusion rule
  func wholeDisks(names []string, isPhysical func(name string) bool) []string
  ```
- Rules: rate = delta / seconds between the two `At`; any delta that is negative, a non-positive time delta or a missing previous value drops that key for this sample only. `cpu/total = Δbusy/Δtotal*100*Cores`; `alert/cpu_high = Δbusy/Δtotal*100` (percent of the whole machine, the allocation being all cores); `cpu/vcpus = Cores`. Memory: `memory/rss = MemUsed`, `memory/cache = MemCached`, `memory/swap = SwapUsed`, `memory/limit = MemTotal`, `alert/mem_high = MemUsed/MemTotal*100` (omitted when `MemTotal == 0`). Network keys per interface: `network/rx:<if>`, `network/tx:<if>` (bytes/s), `network/dropped:<if>` (packets/s). Disk: `disk/read`, `disk/write`, `disk/iops_read`, `disk/iops_write`. `fs/free_percent:<mount>` = `(Size-Used)/Size*100`, omitted when `Size == 0`, `Used > Size` or `!realVolume`. `realVolume` is false for mount points under `/proc`, `/sys`, `/dev`, `/run`, `/snap`, `/var/lib/docker`, `/var/lib/containers` (LocalStorage's `GET /v1/storage?system=show` is already the Disks widget's list; this is the spec's "exclude pseudo, tmpfs, overlay, loop, squashfs" kept as a second guard because that list carries no filesystem type). `wholeDisks` keeps names for which `isPhysical` is true.

  ```go
      Name    func() string                           // the machine's display name (hostname), "" -> "Machine"; used everywhere (events, /v1/sys/stats)
      Boot    func() time.Time                        // boot time, zero = unknown
  }
  type Service struct{ Store *stats.Store; Eval *stats.Evaluator /* unexported rest */ }
  var Default *Service                                // nil until Start succeeded
  func New(cfg Config) (*Service, error)              // opens Store and Evaluator in Dir, store.SetOnMinute(eval.OnMinute), Rebuild(Item)
  func (s *Service) Tick(ctx context.Context) error  // one sample, deterministic, no sleeping
  func (s *Service) Run(ctx context.Context)         // every 5 s until ctx is done; logs a failed Tick, never exits on it
  func (s *Service) Close() error
  func (s *Service) Name() string                    // cfg.Name() or "Machine"
  func (s *Service) BootTime() time.Time              // cfg.Boot(), zero when unknown
  func eventProperties(ev stats.Event, minutes int, name string) (eventName string, p map[string]string)
  ```
- `Tick`: `Read` -> `Collector.Sample` -> `Store.Record(Item, r.At, sample)`; the Store's hook calls `Eval.OnMinute` when that Record writes a minute (the sampler tracks no minute and never calls `OnMinute`). A failed `Read` records nothing (a gap, not a zero, and it resolves nothing), still advances nothing, and the next tick works. `eventProperties`: name `resource:alert-firing` / `resource:alert-resolved`; `item:"host"`, `name`, `kind:"host"`, `situation:ev.Key`, `value:` the value rounded to an integer, `since:` `ev.Since.UTC().Format(time.RFC3339)`, `source:"core"`, `minutes:` the rule's `Minutes` for `ev.Key`. The evaluator's `emit` calls `Publish` in its own goroutine with a 5 s timeout (a slow bus never delays a tick) and `Hub` synchronously.
