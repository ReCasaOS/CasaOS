# AppManagement: Docker sampler and /v2/app_management/stats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `CasaOS-AppManagement` measures every container Docker knows (compose apps and all others) every 5 s, keeps 7 days of history through `pkg/stats` of CasaOS-Common, serves it on `/v2/app_management/stats`, and publishes `resource:alert-firing` / `resource:alert-resolved` on the MessageBus.

**Architecture:** a new package `pkg/dockerstats` holds the pure conversion (Docker stats to `stats.Sample`), the identity rules, a `Source` interface over Docker, and a `Sampler` that ticks every 5 s: list, stats, `Store.Record`. The evaluator is wired once with `Store.SetOnMinute(ev.OnMinute)` (the sampler tracks no minute rollover and has no catch-up loop), and `Evaluator.Resolve` is called when a container stops being measured. `service/stats.go` wires it to the MessageBus and the service lifetime; `route/v2/stats.go` serves the four routes. Nothing in the existing `GET /compose/{id}/containers/stats` path, `pkg/docker/stats.go`, `service/container_stats.go` or `route/v1` changes.

**Tech Stack:** Go 1.26.8, echo v4, oapi-codegen v1.12.4 (codegen is gitignored, generated by `go generate`), `github.com/docker/docker` v28.5.2 client (`api/types/container`, as `service/docker_watch.go` already uses), `github.com/docker/compose/v5/pkg/api` labels, `github.com/ReCasaOS/CasaOS-Common/pkg/stats`, `gotest.tools/v3/assert` (the repo's test style).

## Global Constraints

- Sampling: one measure every **5 s**; history: per-minute avg/min/max kept **7 days** (Common does the storage; this service never writes files itself except through `stats.Open` / `stats.NewEvaluator`). Directory: `/var/lib/casaos/stats/app_management`.
- Budget: this service's sampling at rest stays at or under **0.5 % of one core with 30 containers** (AppManagement process plus the growth of dockerd's CPU). The budget is this service's own; it is not part of a sum with virt's or the core's. Measured in Task 4 and again in Task 9, reported in `docs/stats-sampling-cost.md`.
- Identities (contract): compose container `app:<application>:<service>:<n>` (n = `com.docker.compose.container-number`, "1" if absent), any other container `container:<name>`. Groups: `Conteneurs` / `Autres conteneurs`. Docker's container ID never appears in an identity.
- Routes, behind the existing JWT middleware (no public route): `GET /v2/app_management/stats`, `GET .../stats/{id}?range=live|15m|1h|24h|7d`, `GET|PUT .../stats/{id}/alerts`. Errors: `404 unknown_item`, `400 bad_range`, `400 bad_rules` (message `bad_rules: rules[0].threshold`, contract section 2), `503 stats_unavailable`. No text coming from a container or from Docker's errors in any error message.
- Alerts: `cpu_high` 90 % for 10 min (percent of the **effective CPU allocation**: container limit if set, else the machine's cores), `mem_high` 90 % for 5 min (percent of the memory limit, or of the machine's RAM for a container without one), evaluated on per-minute averages by `Evaluator`; one firing, one resolved.
- Series keys are exactly the contract's (`cpu/user`, `cpu/system`, `cpu/iowait`, `cpu/throttled`, `memory/rss|cache|swap|limit`, `network/rx|tx|dropped:<interface>`, `disk/read|write|iops_read|iops_write`, `pids/count|fds`, `restarts/count`, `health/ok`, `alert/cpu_high|mem_high`). A key absent from a `Sample` means "no data"; never write 0 for "not measured".
- Texts: keys in English, values in French, but this service sends only identifiers and codes (the page translates `notes` codes). A container name is data: it goes into JSON as a string, nowhere else.
- Tests: no real clock (`stats.Clock` injected), `gotest.tools/v3/assert`, files named `*_test.go` next to the code (the repo mixes `_internal_test.go` for package-internal tests; follow that for `service`, plain package tests for `dockerstats`). Windows host: `go test` works for everything except the files tagged `linux` (Task 4 cost test, Task 9 proof) and `go test -race` (needs cgo; the release workflow and `.goreleaser.yaml` run `go test -race -v ./...`): those run in **WSL as root** (or on the QEMU VM if WSL has no usable Docker daemon).
- Commits: conventional style like `feat(watch): ...` in the history, one per task, **no `Co-Authored-By`, no "Generated with", nothing about reviews or the owner**.
- No new Go dependency except the CasaOS-Common bump (`golang.org/x/sync` is already in `go.mod`).

## Extensions (to the contract; nothing renamed)

1. Success bodies are **bare** (`{"items":[...],"notes":[...]}`, the Series object, `{"rules":[...],"active":[...]}`), unlike this service's other routes which wrap in `data` (contract section 2). Error codes travel in the `message` field of the repo's existing `BaseResponse` (`{"message":"unknown_item"}`); `bad_rules` is `{"message":"bad_rules: rules[0].threshold"}` (one shape, no extra property).
2. `scale.cpu_allocation` is a number of **cores**: the container's declared CPU limit when it has one (1.5 means 150 % of one core; the page draws its reference line from it), otherwise the machine's core count and `notes` carries `no_cpu_limit`. `scale.memory_limit` is the declared limit in bytes, or `null` with note `no_memory_limit` (Docker then reports the machine's RAM as the limit; `mem_high` is computed against it, a container holding 90 % of the machine's RAM is worth an alert, and no `memory/limit` series is written).
3. `notes` codes from this service: `no_cpu_limit`, `no_memory_limit`, `container_gone` (history of a container that no longer exists); the list's own `notes` can carry `stats_capacity`.
4. Not produced, because Docker's API has no source for them: **`cpu/iowait`**, **`pids/fds`**, and **`memory/swap` on cgroup v2** (present on cgroup v1 with swap accounting). They are absent series, not zeros; the page must tolerate their absence. `alert/*` series are written but filtered out of the `Series` answer.
5. `range` is a plain string in the OpenAPI (not an enum), validated by the handler with `stats.ParseRange`, so a bad value gives `400 bad_range` rather than the validator's own message; absent means `live`.
6. Docker down: `GET /stats` answers 503 `stats_unavailable` (rows need live state); `GET /stats/{id}` and `/alerts` keep answering from the history on disk (the outage is a gap). 503 on every route when the sampler is not running (the store did not open).
7. The list also holds containers that no longer exist but whose history is within 7 days, with state `stopped`, name derived from the id, no numbers.
8. Compose containers with the project label are `app-container` whether or not CasaOS installed them (the same rule as `service/docker_watch.go`); `compose run` one-off containers (`com.docker.compose.oneoff=True`) are "other" containers.
9. `restarts/count` is Docker's `RestartCount` (restarts by the restart policy); a manual `docker restart` does not raise it.
10. Item header: `started_at` is inspect's `State.StartedAt` and `detail` is the image name (`Config.Image`, cut to 200 characters); both are `null` for a container known only from disk.
11. Capacity: `stats.ErrTooManyItems` from `Record` (256 live items) is logged once per hour, never per tick, and makes the list answer `notes: ["stats_capacity"]` for the next hour; the containers over the cap are listed but not measured.
12. `Evaluator.Resolve(id)` is called at the first tick that sees a container not `running` and at `Forget`. A failed `Stats` call for a running container is a gap (no `Record`, so no `OnMinute`) and resolves nothing.

## Review Focus

Inputs the spec implies and no obvious task test covers, most likely first; each has its test in the task named.

1. A container that is recreated or restarted resets its counters: no negative or enormous rate, a gap instead (Task 2 `TestACounterThatWentBackwardsGivesNoRate`).
2. Docker (or the whole service) was away for minutes: the first sample afterwards must not average the outage into one fake spike (Task 2 `TestAPreviousSampleOlderThanMaxGapIsIgnored`, Task 5 `TestAfterDockerComesBackThereIsAGapNotASpike`).
3. A container on host networking has no interfaces; a paused, `created` or restarting container has no usable stats; a container with no block-IO controller has empty IO lists: none of these may crash or write zeros (Task 2 `TestEmptySectionsGiveNoKeys`, Task 5 `TestOnlyRunningContainersAreSampled`).
4. The URL id round trip: `app:jarvis:web:1` raw and `app%3Ajarvis%3Aweb%3A1`, names with dots and dashes (Task 7 `TestTheIdArrivesDecodedWhetherOrNotItsColonsAreEncoded`).
5. A host with hundreds of containers must not make a tick overrun the next one or open a burst of connections (Task 5 `TestTicksNeverOverlap`, Task 4 concurrency bound 8).
6. A firing container that stops, exits, is paused or is removed resolves exactly once (Task 5 `TestAStoppedFiringContainerResolves`, `TestAnAlertOfAContainerThatDisappearsIsResolved`).
7. A failed `Stats` call for a running container, for minutes, resolves nothing and later fires nothing a second time (Task 5 `TestAFailedStatsCallDoesNotResolve`; Task 1 `TestAMinuteWithoutRecordDoesNotResolve`).
8. The evaluator's files in the shared directory (`alerts.json`, `alerts.json.tmp`) survive `Open` and the hourly `Sweep` (Task 1 `TestSweepKeepsTheEvaluatorsFiles`).
9. The 256-item cap is logged once an hour and shown as a list note, not a flood of errors (Task 5 `TestTheCapacityErrorIsLoggedOnceAnHourAndListed`).

```go
func (s *Sampler) SetRules(id string, rules []stats.Rule) error          // ErrUnknownItem, else Evaluator's error
func (s *Sampler) Close() error
```

**Tick algorithm (decisions, in order):**
1. `now := Clock.Now()`; `List`. On error: mark Docker down (log once at the transition, not every 5 s), record nothing (a gap; no `Resolve` either: Docker being away is not evidence that the alerts ended), return. On success mark Docker up.
2. For each summary, `Identify`; update the registry entry (Docker ID, state, health, name). A new Docker ID for the same identity means "recreated": drop its previous `Snapshot` and force a re-inspect.
3. `Inspect` a container that was never inspected, was recreated, or was last inspected 60 s ago (`// ponytail: polled once a minute instead of following Docker events; limits and RestartCount change rarely and the history is per minute anyway`). It gives `Allocation` (`AllocationOf(resp.HostConfig)`), `RestartCount`, `StartedAt` (`State.StartedAt`) and `Detail` (`Config.Image`, cut to 200 characters).
4. Sample only containers whose `State == "running"`. `Stats` runs under a 4 s timeout. A registry entry whose container is listed but no longer `running` (exited, paused, restarting, created) gets `Evaluator.Resolve(id)` once, at the first tick that sees it so (a flag on the entry, cleared when it runs again).
5. For each measured container, `Measure(prev, stats, now, alloc, 3*Interval)`; add `restarts/count` (if inspected) and `health/ok` (if `HealthOf` is ok); `Record(identity.ID, now, sample)`; keep the new `Snapshot` and the latest `cpu/user + cpu/system` and working set. A running container with no entry in the `Stats` map (failed call) gets no `Record` this tick: a gap, neither a zero nor a resolution. `stats.ErrTooManyItems` from `Record` goes to `noteRecordError` (logged once per hour, sets the `stats_capacity` note for an hour); any other `Record` error is logged at most once a minute.
6. A registry entry not in the list for 2 consecutive ticks is gone: `Evaluator.Resolve(id)` (unless step 4 already did), `Forget(id, now)`, removed from the registry (no `gone` set: `Resolve` ends the alerts at once). A recreated container (new Docker ID, same identity) in the same list is not gone.
7. Once per hour (`lastSweep`): `Sweep(now)`.
8. No minute handling in the sampler: `New` calls `store.SetOnMinute(ev.OnMinute)` once (contract, "Câblage"); there is no rollover tracking, no catch-up loop and no direct `OnMinute` call. The Store calls the evaluator when a `Record` writes a minute.
